# 交付 314（2026-11-05）· 日清单界面改版

代码在 `main` 的 `cbb7868`：日清单从「一列长清单」改成 **左栏集合 + 中间看板三列 + 右侧详情**，
网页与原生用同一套设计；原生新增「标记完成」。这一版是**可体验版**，不是正式发布。

## 一眼看变化

- **360 手机**：顶部「孩子切换 → 今天 N 件事+进度 → ＋补录/集合胶囊 → 今天要做」，卡片按科目分组，
  每张卡 1–2 条要点 + 徽章（明天带 / 不用录音 / 需家长签字 / 周五交…），点开是底部详情；
  底部只剩站点导航（去掉了原来压住内容的悬浮条）。
- **1440 桌面**：左栏（孩子切换、集合计数、日历/课表、主导航）/ 中间看板（今天要做 · 明后天 · 已完成）/
  右栏详情（发布/完成/截止数据格、要做什么编号、不做什么、家里的安排、后续通知、来源消息、三个动作）。
- **详情不再重复**：以前「要做什么」里会重复标题、家里安排混在正文里、后续通知和当前要求并列；
  现在正文只留当前生效要求，家里安排与后续通知各自独立成块，同一句不会出现两次。
- **原生与网页一致**：原生 `Workspace.swift` 同一套三档布局，并新增「标记完成」（`POST /api/task`，
  与网页勾选完成同一条写入）。

## 已知缺口（如实）

1. 手机「集合胶囊 / 孩子切换 / 看明天」按钮 30–32px，低于 44px 点击区（改高会顶破「头部+胶囊 ≤150」）。
2. 手机点开详情后，上方只完整可见 1 张卡（设计稿写 ≥2）。
3. 手机首卡 top 281px（因为保留了吸顶的日历/课表单行条，`test_calendar_learning_ui.cjs` 依赖它）。
4. 原生三档没做可见窗口验收（本机静默规则），只做编译 + 锚点核对；`<900` 原生档受 `main.swift` 最小宽 900 限制走不到。
5. 原生「标记完成」按 `app.py:1853` 契约实现、未实际点击验证；不传 `expected_updated`，多设备并发时没有冲突提示。
6. 「已取消」的判定依赖文本匹配（网页 `calendar.js` 与原生 `isCancelledItem` 同口径），不是结构化状态。
7. same-fold（老师同一要求重复提醒）的原文仍逐行保留在详情里（显示层不做语义合并），属下一轮。
