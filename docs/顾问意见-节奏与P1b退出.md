# 顾问意见：统一P1b退出口径与本周节奏

## 背景

当前产品开发正处于P1a/P1b向P2阶段过渡的关键期。本文档针对进度汇报口径与本周执行节奏提供清晰、可操作的过程建议，供开发团队吸收到统一PRD（PRD.md）中。

**文档性质：** 纯过程建议，不改变产品代码、测试、打包或家庭配置；不变更产品优先级（每日待办第一优先保持不变）。

## 相关背景资料

- 统一PRD：[PRD.md](../PRD.md)
- 参考意见：[PR #270 诊断意见](https://github.com/joyrush-D/family-learning/pull/270) 和 [PR #271 快捷操作候选](https://github.com/joyrush-D/family-learning/pull/271)
- 已合并：[PR #279](https://github.com/joyrush-D/family-learning/pull/279)（P1b软件退出已在PRD中声明通过；四项反例已修复并验证）
- 家庭当前版本：r300（未升级到最新代码；合成样本通过不等于真实来源/家长验收）

## 核心建议

### 1. 确认P1b退出口径已一致

**现状：** PR #279已合并；PRD.md中P1b软件退出已声明通过。

**建议：**
- 核对PRD.md §5（P0/P1表格）、§10（实现路线）、§11（评审记录）与已合并的PR #279四处表述是否一致
- 如发现任何遗留的"仍需P1b补齐"或"等待P1b"的过时表述，将其更新为：
  - 已完成：标注"已在P1b完成（提交XXX/PR #279）"
  - 未完成：标注"移至P2/R0X继续"

**目标：** 确保外部读者（包括独立顾问评审）从PRD.md可以清楚判断当前阶段与未完成项。

### 2. 真实来源与家庭验证仍待确认

**现状：** 合成样本测试通过，家庭仍在r300未升级。

**建议：**
- 在声称"可部署到家庭"之前，明确完成真实来源（微信/QQ）抽查回放或家庭机器现场验证
- 如真实来源/家长验收仍待进行，在PRD.md §7或§10明确标注"已通过虚构样本，真实来源待验"
- 保持r300与新版本之间的验收差距透明，不因"冻结样本全绿"就直接声称家庭已可用

### 3. 本周节奏：不并行新入口或大规模重构

**建议：**
- PR #279的四项反例（日期角色、疑惑归属、录音提交步骤、旧待办继续）已修复并合并
- 本周（或本轮迭代）不并行新增功能入口、UI重排或大规模结构调整
- 已有功能缺陷修复正常进行，但新特性扩展等待P2明确范围

**目标：** 保持一周内交付清晰、可验收，避免多线并发导致验收混乱。

### 4. 真实来源回放或家庭现场验证的门槛

**建议：**
- 在将家庭版本从r300升级之前，至少完成以下之一：
  1. 真实来源（微信/QQ）的抽查回放，明确确认消息采集与归并逻辑
  2. 家庭机器的现场集成测试，覆盖完整家长操作路径
  3. 独立验收确认软件退出标准（PRD §6 AC条件）实际满足
- 不因"冻结样本全绿"就直接升级到未经真实验证的新版本
- 在PRD.md中明确标注当前验证状态（如"已通过虚构样本，真实来源待验"），保持透明

### 5. 协作看板应仅挂当前P2关键路径

**建议：**
- 协作看板（协作看板.md）本周只列当前阶段的"阻断性"或"本周明确要完成"的任务
- R01–R34全量需求保留在PRD.md §9，不需要全部搬到看板"本周工作"栏
- 看板行应包含：
  - 负责人
  - 任务简述
  - 当前状态（待开始/进行中/受阻/已完成）
  - 依赖与验收标准

**目标：** 让团队和外部读者快速看到本周关键路径，而不被长需求列表淹没。

### 6. 保持"每日待办优先"不变

**明确：**
- 用户已确定当前执行优先级为：
  1. 每日待办与孩子口头补录
  2. 作业反馈、书写检查、错题整理与订正
  3. 自动准备/执行、预审与参考答案
- PR #270虽建议"错题本优先/每日待办降级"，但该建议**未被采纳为本轮路线**
- 本文档不改变上述优先级；所有P1b退出、本周节奏建议均在此优先级框架内执行

### 7. （可选）小步标记四年级痛点而非完全推迟

**背景：** 用户提到四年级孩子的英语间隔复习与单个数学概念检查需求实际存在，不应因P1/P2聚焦而完全遗忘。

**建议（可选、低优先）：**
- 在PRD.md §9或§17–§20相关行中简短注明：
  - "四年级英语间隔复习最小可用版（R20部分）计划在P3/P4验证"
  - "四年级数学单概念检查（R17/R19部分）计划在P3/P4验证"
- 此注释不构成本周工作，也不意味着P1b必须包含这些功能
- 目的是保持需求可见性，避免晚期才发现四年级核心痛点完全缺失

## 总结

本文档的核心诉求是**过程透明与口径一致**：

1. **确认退出口径一致：** PR #279已合并，确认PRD.md各处（§5/§10/§11）表述一致，清除任何遗留的"等待P1b"措辞
2. **如实标注验证范围：** 虚构样本通过≠真实部署可用，明确标注真实来源/家庭验证状态
3. **本周聚焦收敛：** 不并行大规模新入口或重构
4. **看板轻量化：** 看板仅挂当前P2关键路径，全需求在PRD.md维护
5. **优先级不变：** 每日待办第一优先保持，不因本文档改变
6. **可选四年级标记：** 低优先，仅为避免晚期才发现核心痛点遗漏

这些建议供M4 Claude（实现方）与Codex（验收/统筹方）吸收到PRD.md相应章节，并在实际执行中保持一致。
