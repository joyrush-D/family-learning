# 顾问意见：统一P1b退出口径与本周节奏

## 背景

当前产品开发正处于P1a/P1b向P2阶段过渡的关键期。本文档针对进度汇报口径与本周执行节奏提供清晰、可操作的过程建议，供开发团队吸收到统一PRD（PRD.md）中。

**文档性质：** 纯过程建议，不改变产品代码、测试、打包或家庭配置；不变更产品优先级（每日待办第一优先保持不变）。

## 相关背景资料

- 统一PRD：[PRD.md](../PRD.md)
- 参考意见：[PR #270 诊断意见](https://github.com/joyrush-D/family-learning/pull/270) 和 [PR #271 快捷操作候选](https://github.com/joyrush-D/family-learning/pull/271)
- 当前草稿：[PR #279](https://github.com/joyrush-D/family-learning/pull/279)（P1b草稿，PR正文仍说"4待审/0正式回放"，而PRD.md已说软件退出通过）
- 家庭当前版本：r300（未升级到最新代码）

## 核心建议

### 1. 统一三处P1b退出声明

**问题：** 当前PR #279正文、草稿标题/状态与PRD.md §10/§11的退出表述不一致，导致外部读者无法判断P1b是否真正完成。

**建议：**
- 如果P1b软件退出条件已全部满足，则：
  - 更新PR #279正文，说明原"4待审/0正式"的四项已如何解决（日期角色、疑惑归属、录音提交流程、旧待办继续执行），并引用具体提交或检查结果
  - PR标题移除"draft"或改为"Ready for review"
  - PRD.md §10与§11的P1b行保持一致的"软件退出已通过"表述
- 如果四项仍未全部解决，则：
  - 在PRD.md §11中明确将未解决的子项移入R07–R09或P2相关行，注明为后续改进点
  - PR正文与PRD一致说明"P1b部分完成，剩余X项已移入P2"，并停止声称"已退出P1b"

**目标：** 让外部读者（包括独立顾问评审）能够从单一信息源（PRD.md）清楚判断当前阶段与未完成项。

### 2. 修正P0表格中的过时表述

**问题：** 如果PRD.md中仍有"原件全链条仍需P1b补齐"之类的说辞，但P1b已宣布退出，则前后矛盾。

**建议：**
- 检查PRD.md §5的P0/P1表格，将任何"等待P1b"的表述更新为实际状态：
  - 如已完成，改为"已在P1b完成（提交XXX）"
  - 如未完成，改为"移至P2/R0X继续"
- 确保表格注释、路线说明与§10/§11的退出记录一致

### 3. 本周聚焦：仅关闭四项待审反例

**建议：**
- 本周（或本轮迭代）仅处理PR #279正文提及的四项具体待审反例：
  1. 日期角色混淆
  2. 疑惑/怀疑归属不清
  3. 录音提交步骤不明确
  4. 旧待办安全继续逻辑
- 不在本周并行新增功能入口、UI重排或大规模结构调整
- 已有功能缺陷修复正常进行，但新特性扩展等待P2明确范围

**目标：** 保持一周内交付清晰、可验收，避免多线并发导致验收混乱。

### 4. 合成样本通过 ≠ 可部署

**问题：** 冻结的虚构样本测试通过，不等于真实来源、真实家庭场景已可用。

**建议：**
- 在合并PR或声称"已可部署"之前，至少完成：
  1. 真实来源（微信/QQ）的抽查回放，或明确说明真实来源仍待验证
  2. 当前家庭环境（r300或新版）的集成测试
  3. 软件退出标准（PRD §6 AC条件）与独立验收的一致确认
- 不因"冻结样本全绿"就直接将家庭版本从r300升级到未经真实验证的新版本
- 在PRD.md §7或§10明确标注"已通过虚构样本，真实来源待验"，保持透明

### 5. 协作看板应仅挂当前P1b→P2关键路径

**建议：**
- 协作看板（协作看板.md）本周只列当前阶段的"阻断性"或"本周明确要完成"的任务
- R01–R34全量需求保留在PRD.md §9，不需要全部搬到看板"本周工作"栏
- 看板行应包含：
  - 负责人
  - 任务简述
  - 当前状态（待开始/进行中/受阻/已完成）
  - 依赖与验收标准

**目标：** 让团队和外部读者快速看到本周关键路径，而不被长需求列表淹没。

### 6. 保持"每日待办优先"不变

**明确：**
- 用户已确定当前执行优先级为：
  1. 每日待办与孩子口头补录
  2. 作业反馈、书写检查、错题整理与订正
  3. 自动准备/执行、预审与参考答案
- PR #270虽建议"错题本优先/每日待办降级"，但该建议**未被采纳为本轮路线**
- 本文档不改变上述优先级；所有P1b退出、本周节奏建议均在此优先级框架内执行

### 7. （可选）小步标记四年级痛点而非完全推迟

**背景：** 用户提到四年级孩子的英语间隔复习与单个数学概念检查需求实际存在，不应因P1/P2聚焦而完全遗忘。

**建议（可选、低优先）：**
- 在PRD.md §9或§17–§20相关行中简短注明：
  - "四年级英语间隔复习最小可用版（R20部分）计划在P3/P4验证"
  - "四年级数学单概念检查（R17/R19部分）计划在P3/P4验证"
- 此注释不构成本周工作，也不意味着P1b必须包含这些功能
- 目的是保持需求可见性，避免晚期才发现四年级核心痛点完全缺失

## 总结

本文档的核心诉求是**过程透明与口径一致**：

1. **统一退出声明：** PR正文、PRD.md、看板三处对P1b状态的描述必须一致
2. **如实标注范围：** 虚构样本通过≠真实部署可用，明确标注真实来源/家庭验证状态
3. **本周聚焦收敛：** 只关闭已明确的四项待审反例，不并行大规模新入口或重构
4. **看板轻量化：** 看板仅挂当前关键路径，全需求在PRD.md维护
5. **优先级不变：** 每日待办第一优先保持，不因本文档改变
6. **可选四年级标记：** 低优先，仅为避免晚期才发现核心痛点遗漏

这些建议供M4 Claude（实现方）与Codex（验收/统筹方）吸收到PRD.md相应章节，并在实际执行中保持一致。
