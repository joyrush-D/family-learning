# 家庭学习与成长助手

一个进入家庭试用的开源项目：帮助家庭汇总学校通知、跟踪学习进展，记录孩子的兴趣与成长，并回顾哪些支持方式有帮助。产品目标是家长用得省事、孩子愿意参与且留下可比较的成长证据；功能数量、记录数量和积分都不代表教育效果。

时间管理是核心业务：把放学后的作业、活动和休息放在同一张时间账里，比较计划用时、实际用时和结果，逐步减少无效耗时并保护休息。用时变短不能单独算进步，还要看工作量、完成质量和所需帮助。

当前状态：已有可部署的网页应用，支持认证反向代理访问、Three.js成长场景、记录能量与徽章、待办反馈、原件上传、模型图文草稿及人工核对、按孩子问答与出处跳转、成绩与订正复测关联、阅读作品与约定印章及兑现、文件勾选与批量打印队列、备份恢复。源码已公开，公开克隆后的干净安装核验通过。本轮版本为 [v0.1.0-alpha.1 家庭试用版](https://github.com/joyrush-D/family-learning/releases)，版本标签与源码下载见版本页面。完整V1仍在验收；实际手机操作与真实到期回看尚未完成。

家庭日历已部署用于家庭试用，浏览器、API与备份检查通过；实际手机操作和家庭使用反馈仍待验收，不代表完整V1已交付。

### 在父母的 iPhone 查看安排

从已登录的 HTTPS 家庭入口打开“日历 → 同步到手机”，复制订阅地址。在 iPhone“日历 → 日历列表 → 添加日历 → 添加订阅日历”中粘贴；父母各自添加一次。按提示填写家庭网页的服务账号与密码，浏览器登录不能代替日历认证；这里不需要向本应用提供 Apple 账号。操作路径见 [Apple 订阅说明](https://support.apple.com/zh-cn/102301)。本地 HTTP 地址不提供手机分享。

订阅只读，新增、改期和取消仍在本系统完成；刷新由手机控制，不承诺即时提醒。仅订阅事件标题、参加孩子、日期时间、状态及地点，不包含原始消息、备注、成绩或附件；暂定和时间待定会标明，取消或明确不参加会反映在订阅中。课表节次暂不输出为手机事件，也不自动添加闹铃。夫妻不同 Apple 账号分别订阅，同一账号是否同步至其他设备由其 iCloud 设置决定。

后台提供 `calendar.ics`，沿用家长访问认证；部署者不能为订阅开放匿名访问。本轮接口与浏览器验证不代替真实 iPhone 的账号认证、刷新及使用验收。

## 第一版范围

软件交付、家庭试用和开源发布分别验收、并行推进。连续试用按实际启用后的第7、14、28天回看家长操作负担、孩子自主选择与延迟后的独立表现；等待真实反馈不阻塞仍可进行的开发。方案见[V1交付目标](V1交付目标.md)，这些检查点尚无实际结果。

- 家长通过文字、图片或文件提供信息；消息接入只处理明确指定的来源。
- 按孩子整理通知、截止时间和待办，保留原始出处，区分已整理与已完成。
- 记录成绩、考试范围、失分点和复测结果；区分作业完成与知识掌握。
- 记录孩子自述、父母观察和老师反馈，保留情境，不自动生成性格或心理诊断。
- 形成每周回顾，展示进步、困难和少量可执行建议，允许家长和孩子纠正记录。

## 实现顺序

1. 先用真实家庭流程验证信息采集、去重、记录纠正和每周回顾。
2. 再做可独立运行的最小本地应用：两个孩子的档案、统一收件箱、待办和成长时间线；以手动输入和文件导入完成端到端流程。
3. 当前家庭安装已通过现有微信CLI只读采集指定班级群；独立安装仍需按环境配置采集方式，后续再增加通用连接器和复习工具。读取能力不代表所有用户可直接使用，也不代表历史和附件已全部读完；应如实显示登录状态、实际覆盖区间及未读内容。

第一版不引入完整教学平台、自动排名、心理评分或多家庭云服务。界面和技术栈在实际开发时按最小可用需求确定。

## 每家独立运行与家庭盒子方向

交付主体是完整网页应用、后台与家庭数据；Skill/CLI负责接入，Agent负责有依据的学习支持与回看。同一份源码先能在普通电脑或自有服务器运行，未来可预装到家庭计算盒子。每家独立初始化自己的档案、模型配置、微信/QQ登录和授权群，不附带任何其他家庭资料或账号。

盒子运行应用与盒子运行全部模型是两项能力。先支持本地保存和基础操作，再由家庭选择适用的本地模型或外部API；外部API会接收本次调用所需资料，不能宣称此模式数据从不离开盒子。硬件要求依据实际照片理解、中文转写、问答质量、等待时间和整机恢复测试确定，目前没有验证过的整机型号或一键装机方案。

当前独立安装需配置认证、系统定时器、消息CLI、模型/转写及打印能力。已提供独立Agent进程与CLI采集器，由操作系统定时运行、提前保存建议和站内提醒，不依赖Codex或网页访问。安装和恢复见[独立运行Agent](AGENT运行.md)。现有微信读取和语音/打印链路仍有系统及设备依赖。微信/QQ只用已授权CLI/API，读取班级群与微信对话入口分别验证，未登录或未读取的内容显示缺口。不能据此承诺任意小盒子接电即可全功能运行。

## 一起试一题

家长在“学习进展”的已有记录旁点“一起试这题”，填写本次题目，明确勾选孩子可见的原件，并提供核对过的参考；原记录备注和原件不会默认分享。参考仅供已配置的模型核对，不直接提供给孩子下载；不要填写与本题无关的家庭隐私。已分享的材料保留原样，发现错误时停止分享并重新准备，避免旧尝试悄悄换了题目。

孩子用自己的邀请进入营地，先用文字、照片或语音留下思路或卡点，再按需获取一个提示，随后再次表达；可以找家长、暂停或跳过。原件保留，语音转写须核对再使用；PDF等暂不能直接送入提示模型，缺少可读材料时继续保留表达并提示补充文字。模型失败不会阻止手动记录。每次提示需要孩子主动点击，系统不会自行连续提问。

家长可回看原始尝试、实际提示和再次表达；原始尝试不覆盖，纠正追加关联观察。帮助情况保留孩子自述，同时记录该次表达前实际已有几条系统提示，不把没有选帮助当成独立完成。下一次可从原记录准备相近新题，明确材料关系；“约定再试”打开现有日历表单，日期和时间由家庭商量后保存，不自动安排。

当前为一个知识点的短流程，不自动判定掌握、完成学校作业或发放奖励。模型校验和提示可能出错或给得过多，家长应回看纠正；程序在模型报告题目与参考冲突或无法核对时停止展示解题提示，不保证识别所有错误。只向本家配置的模型发送这道题、参考和本人的已保存尝试；使用外部模型时须按实际孩子年龄、地区和所选服务确认适用条件。

本轮已通过隔离虚构家庭后端及360/1440 CSS像素浏览器流程检查，并用现有本地模型检查错误思路、错误参考、短篇依据、暂停及模糊原图；家庭试用部署另留核验记录。检查入口为 `python3 test_guided.py`、`python3 test_llm.py` 和 `node test_guided_ui.cjs`，浏览器依赖沿用下文配置。真实手机、孩子意愿及延迟后的独立表现需另行试用，不能由隔离测试推断。

## 运行与数据

Python 3.10及以上，基础后台无需第三方Python依赖。在应用目录运行 `python3 app.py`，打开 `http://127.0.0.1:8765`；空家庭直接进入网页初始化。命令行首次初始化仍可使用 `python3 init_family.py`，交互填写孩子称呼和年级；已有家庭资料会拒绝初始化。实际姓名建议交互输入，避免进入终端历史。

### 新家庭与设置

新 Mac mini 或其他主机先安装并启动同一份应用；本项目负责应用内配置，不负责安装微信、QQ、模型应用或迁移个人登录态。

1. 空家庭启动后自动进入“家庭设置”，填写一个或多个孩子的称呼、年级、班级；已有家庭可从页面顶部进入该入口。添加和更正沿用稳定孩子编号，既有记录不会因改名而另建一个孩子。
2. 在消息来源中填写平台、群名称、已核对的群号或 chatroom ID、归属孩子，并分别启用或停用；一个孩子可绑定多个群。本轮需填写明确 ID，没有自动枚举群列表。新微信来源从本机可读取记录起点分批读取，界面保存配置不表示全部历史已覆盖；旧来源保持已有游标。已有历史来源不能通过改名或改绑转给另一个孩子，停用保留历史与游标。QQ 原生历史未就绪时继续显示缺口。
3. 模型可稍后配置。设置页保存家庭自己的服务地址、模型名与可选密钥到私有配置；已有服务器环境变量优先，不把已有密钥回显到浏览器或改写为另一份。保存后可点“检查已保存的连接”，只发送固定测试文字，验证模型响应及要求的返回格式；图片、语音能力另行验证。保存配置不代表模型调用或群读取已通过。
4. 微信／QQ 在消息所在电脑登录，按 [AGENT运行.md](AGENT运行.md)配置实际可用的 CLI 和定时采集。页面显示实际连接结果及最近成功读取；没接好也可先手动记事、上传资料和安排功课。

首次初始化、添加孩子、来源及模型配置已通过隔离 API 和 360／1440 CSS 像素浏览器流程验证，并通过空家庭源码包启动检查；实际手机、全新 Mac 整机和第三方登录兼容仍需实测。不要在已有家庭目录重复运行初始化或用示例覆盖私有配置。

### 新 Mac 的应用运行配置

已有 Python 和本应用源码后，在应用目录运行 `python3 configure_mac.py` 只看配置计划；需要应用随当前用户登录运行时，执行 `python3 configure_mac.py --install`。该命令仅安装本应用的网页、每分钟 Agent 检查、保持运行并每轮间隔 5 分钟采集的三个登录服务，并创建私有采集配置；不安装或登录微信、QQ、CLI或模型。未发现消息 CLI 时不加载采集服务，仍可打开网页填写家庭资料和手动记录。

若刚才在终端手动运行了本应用的 `python3 app.py`，先在原终端按 Ctrl+C 停止它，再安装登录服务，避免占用同一端口。也可以直接安装服务，无需先手动启动；已有家庭服务按升级流程维护，不重复安装。

微信 CLI 默认从当前 PATH 查找，也可用 `--wechat-cli` 指定已有可执行文件；`--qq-cli` 指定已有兼容只读 Python 脚本。只想生成文件供检查，可用 `--output-dir` 指向一个不存在的新目录。发现已有家庭服务、采集配置或端口占用时拒绝安装，不能用它覆盖原有家庭部署；Mac 休眠、关机或退出登录时服务不会持续工作。更多运行与恢复说明见[AGENT运行.md](AGENT运行.md)。

`python3 test_configure_mac.py` 已在隔离环境检查路径、文件权限、计划生成、拒绝覆盖与安装失败撤销；未据此宣称在一台全新 Mac 完成实际服务安装或冷开机恢复。

网页读取本地家庭Markdown台账；网页新增记录、编辑历史和事项状态保存于 `private/family.sqlite3`。消息采集与整理按独立的例行任务提前保存，网页刷新只读取已保存资料，不触发微信或QQ采集或模型调用。记录实际完成状态时须补充依据。SQLite与私有附件一起备份，避免丢失。

页面脚本、样式和Three.js在服务启动时预先打包/压缩，保留服务器内存缓存；浏览器保存静态资源，每次访问校验ETag，内容未变返回304，不再下载正文。未使用内容版本的资源URL每次校验，代码更新后自动重建并下发新版。`Cache-Control: private, no-cache`允许私有缓存并要求校验，并非禁止存储。较大的JSON响应也使用压缩传输；家庭数据接口、原件和孩子会话继续`no-store`，读取最新保存内容，不会用定时快照覆盖刚提交的记录。基础运行无需增加缓存服务。用`python3 test_http_cache.py`检查压缩、版本更新、访问边界与数据新鲜度。

每条成长记录可展开“查看更正历史”，按需读取当前版本和全部已留存旧版本；可比较分数、说明、日期、当时称呼、来源与原件关联。旧版本不作为新进展，也不会自动覆盖当前记录。损坏快照和缺失原件会单独提示，其他版本仍可查看；未保留附件字段的旧版本不据此认定从未有原图。历史原件只在点击后打开，读取失败可重试。此流程复用现有修订表，随同主库备份恢复；`python3 test_app.py`包含只读、历史顺序、原件缺口及访问边界检查。

来源整理按独立会话进行：一个孩子可以对应多个已授权群，各群分别维护采集游标、最近成功读取时间和内容缺口。同一通知跨群出现时，应合并事项并保留多个来源；主要群用于突出展示，不得因此遗漏其他授权群。班级群信息读取不依赖微信对话机器人，未读附件和未覆盖历史继续单独记录。

默认仅监听本机回环地址，禁止直接暴露至公网。可选的手机访问方式是Tailscale Serve：由其提供HTTPS和身份认证，设置FAMILY_HOST与FAMILY_USER，只允许指定账户访问；需要管理员启用Serve以及手机登录同一Tailscale账号。本项目不启用Funnel。

已支持网页上传照片、PDF、办公文件、文本与语音原件，单文件最多20MiB；可关联成长记录，未关联文件保留在待整理资料。支持浏览器录音（需HTTPS或localhost及麦克风权限），上传失败可重试。配置模型后，文字与JPEG/PNG/WebP图片可生成待核对草稿；每次最多3张且合计不超过20MiB。草稿不会自动入档，需填入表单、人工纠正再保存。配置语音服务后，录音可转为可编辑文字，再整理草稿。PDF、办公文件和HEIC目前只保留原件，尚未自动解析。可用手机键盘语音输入文字后整理；教材支持仍为规划。

## 自有服务器部署

可将同一程序部署到自有Linux服务器，以systemd运行，保持监听127.0.0.1:8765，通过SSH隧道访问：`ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 user@server`。无需增加框架或数据库服务。仅监听回环不隔离服务器同机用户，应使用受信任的服务器账号环境。

迁移时先停止旧实例写入，用SQLite backup生成一致副本；服务器数据库成为唯一主库。消息采集电脑向主库提交已授权消息并由服务器确认游标；旧文件同步只上传原有台账、状态及必要附件，不以本地数据库覆盖主库。已验证认证HTTPS反向代理入口及桌面读写；真实手机操作尚待验收。现有微信CLI负责指定群的信息读取，未来微信对话Agent的接入另行验证。

待办支持手动新建、勾选确认完成、取消勾选恢复跟进、按孩子和状态筛选，以及追加进展反馈。每条未完成事项另有“不参加 / 不用做”入口：明确选择“不参加”或“无需处理”后移到“已搁置”，可以恢复跟进，说明可留空，决定本身仍记入历史。搁置不代表完成，不增加学习记录或奖励，也不会向学校发送消息。关联功课停止计时并保留已记用时，不再计入剩余工作；日历保留学校原安排，另标家庭决定，并仅释放该孩子的对应可用时间。勾选只记录家长的确认，不代表系统核实了实际完成。事项历次状态与说明保存在task_history，旧状态会在首次更新时保留。手机采用底部导航和底部反馈表单，桌面保留侧栏。

## 事项的下一步与回看

借鉴 [GTD 的澄清与组织流程](https://gettingthingsdone.com/what-is-gtd/)，沿用已有事项编号管理家庭决定。卡片直接展示要求、下一步、原截止和当前反馈；出处与历次记录按需展开。日历准备备注、阅读分享方式及完成条件、放学后功课的原要求同样直接可见，避免开始行动前逐个找详情。

在“安排下一步”中写一个具体动作，再选择“下一步可以做”“等待别人／条件”或“改天处理／以后再说”。等待需填写对象或条件，可约定回看日期；改天也可不定日期。到回看日期后，未关闭事项重新出现在“下一步”和首页“今天回看”，供家庭决定是否继续推进。原学校截止时间与日历不会被推迟或覆盖；原截止恰好在今天的事项仍显示在首页。已加入放学后计划的功课和计时需在原处调整，本入口不擅自停止或重排它们。

这不是第二套任务库，也不是新的完成状态。完成仍需确认，暂不参加或无需处理仍进入“已搁置”；这些安排不增加成长记录或奖励。问答证据包含家庭安排与等待条件。页面到期回看不代表已发送微信或手机通知；每周完整 GTD 回顾及多步骤项目依赖尚未实现。

本轮用虚构家庭检查多端关键内容可见、保存重试、并发更正、等待／改天后回看、权限边界与备份恢复；实际手机和家庭长期效果仍需试用。

## 放学后的时间管理（家庭试用已部署）

本轮增加家长与孩子共同使用的每日时间页：放学后说清今天有哪些功课，复用已有待办或手动补充，给每项一个预计分钟数。晚饭、运动和课外活动继续放在原日历；按家庭明确设置的停止学习时间查看可用时间，不预填成已经同意的作息。

做一项时开始，休息或离开时暂停，结束后选择“完成”“做了一部分”或“需要帮助”，可补充帮助和卡点；忘记计时可以补录并标为补录。暂停不改变作业完成状态；保存本次结果时，计划、已记录用时、结果和说明归档为普通学习记录，可以从“学习记录 / 后续尝试”继续跟进。近7天按实际有记录的日期回看，不把漏记当零分钟，也不做效率分或兄弟排名。

关闭页面不会自动暂停。较早日期仍在运行的计时可打开原日期核对；跨日、异常长计时等显示用时待核对，不纳入确定的实际分钟。从备份恢复时，原先运行中的计时暂停并标为待核对，保留已保存的用时，需按实际情况补录后再继续，不把停机期间自动算作学习。

这条流程不依赖LLM，手机键盘语音可代替打字。照片和语音原件仍可用原有输入流程保存，但本轮不声称拍照已能自动拆分整张作业单。家长可协同记录，也可逐孩开启“每天的功课”，让孩子从独立入口报功课、计时和反馈，结果由家长核对；阅读与短引导分别逐项、逐题分享。2026-09-08已完成时间管理家庭试用部署，桌面与窄屏隔离流程、正式入口读取及原有记录保留已核对；实际手机、家庭使用和节时效果尚待验证。具体规则见[PRD的FR18](PRD.md#fr18-放学后时间管理)。

## 主动陪伴的最小架构

现有Python后台、SQLite、附件与网页继续复用。`family_collect.py`通过已授权CLI采集，`family_agent.py --once`独立处理增量消息、学习记录及到期反馈；系统定时器定期执行，不依赖Codex会话。来源游标、工作状态和提醒保存在同一主库，网页只读取结果。首页孩子卡片显示少量有出处的提醒，学校草稿经家长核对后加入原有待办，学习跟进复用原记录反馈。已有即时整理与问答继续使用同一模型接口。没有增加Agent框架、向量数据库或另一套业务数据库。

场景顺序：考试前核查范围与困难，考试后记录错题、订正和复测；情绪与同伴交往从具体事件和孩子意愿出发；本地消息核查官方来源、有效期、适龄和成本。建议不承诺提分、不诊断、不自动报名。地点未知时不生成区域推荐。

旧版建议兼容路径由采集端写入私有目录的陪伴建议.json列表，经既有同步流程送到后台；独立Agent的新提醒和处理状态保存于主库，不写回该文件。旧文件不存在文件时显示空状态，损坏不影响其他记录。每条包含id、child、topic、title、evidence、action、review_on、expires_on。记录反馈使用既有records表，source为“陪伴建议:ID”；独立Agent定时复用其到期规则，过期旧建议不作为当前有效建议展示。图文草稿已经实测；本地语音转写已验证，讯飞数据直连仍待实现。成绩记录可通过“跟进 / 复测”关联订正、复测或补充观察，禁止关联到另一个孩子或形成循环。自有部署可通过经过认证的HTTPS反向代理提供手机入口，实际手机操作需要单独验证。

陪伴反馈沿用原表单，家长可选择“只记录反馈”“愿意试试”“暂不考虑”或“改天回看”，也可保留文字、照片及语音原件。明确选择保存后立即影响展示和回看安排；延期须指定北京时间今天之后的日期。“愿意试试”只表示意愿，不表示孩子已完成，不发奖励，也不延长过期建议。只记录反馈不改变原决定，不根据正文关键词猜测采纳或停推。

每次明确选择追加保存于原成长记录，新选择优先于旧提醒文件中的安排；更正早期记录的文字不会重新应用旧选择，调整选择须追加反馈。重复提交同一请求只保存一次，结果不明时用原请求核对重试；若已有更新选择，以后台当前安排为准。此状态与反馈历史随主库备份恢复。

`python3 test_followup.py`、`python3 test_review.py`和`python3 test_backup.py`包含选择、回看及恢复检查；`node test_care_ui.cjs`使用隔离虚构家庭核对360与1440 CSS像素下的明确选择、日期、失败重试与表单重置，沿用上述Playwright运行环境配置。此检查不代替真实手机操作或家庭回看反馈。

## 本地回看检查

初始化并运行应用后，在主库所在机器执行 `python3 family_review.py`。它复用现有孩子归属、建议与反馈读取规则，以北京时间检查到期或错过日期的建议，并输出需要核对的反馈；无需模型、Codex运行时或新增服务。独立目录可用 `--root 家庭目录 --data 私有目录` 指定，默认使用程序目录及现有 `FAMILY_DATA` 配置。

命令只读数据库、建议和提醒状态，原子保存权限为0600的 `private/回看检查.json`。完整待处理候选保留在报告中，实质内容无变化时标准输出为空；调用方仍须查看退出码与报告，空输出不等于没有未处理事项。退出码1表示存在读取或保存问题；故障时保留可核对的旧候选并标明当前来源无法核对，不能把来源缺失或损坏当成无需回看。

明确停推和延期继续有效；新的自由文本只作为待核对依据，不按关键词推断采纳、恢复推荐或孩子完成。过期建议需要重新核实，不自动续期。原件仅列关联ID并标记正文未读。检查报告不修改 `last_notified` 或家长状态，也不表示通知已送达；建议的解释、处理与通知仍由实际运行的Agent或家长完成。

该检查命令不自带调度器；独立Agent运行时直接复用同一到期规则，调度由操作系统负责。检查报告是可重建资料，不代替家庭原始备份，恢复后可重新生成。`python3 test_review.py` 使用虚构资料验证日期、停推延期、同孩反馈、只读与故障恢复；真实到期回看与家庭效果另行验收。

## 家庭日历（家庭试用已部署）

本轮增加按日、周和周末查看学校课表、明确日期的学校事项与家庭课外安排。支持多个孩子和共享安排：电脑以周视图查看，手机使用日期选择与当天议程。来源保留出处与关联事项；课表只有节次时按节次显示，不推算上课钟点。未明确的学校日期保留待核对，不由系统补出确定日期。

### 一句话查安排、建草稿

从日历点“说一句安排 / 查询”，或打开“问问助手”。查询先选孩子，例如“下周末有什么安排”；默认按问题里的常用日期表达检索，也可展开“限定查询日期”。回答显示实际范围，出处可以打开那一天的日历或课表。未录入、来源失败或只知道节次都不能说明孩子有空。

输入“周六下午三点带两个孩子去公园”，点“整理成日历”，核对参与孩子、日期和时间后点“保存安排”。没说清的孩子、日期不自动补成全家或今天，钟点与地点可留空。草稿默认暂定，关闭后可在本次页面会话继续核对；原保存回执未确认时先重试原请求，避免重复创建。可以用手机键盘语音输入，也可把现有录音转写带入同一入口。模型不可用时仍可手动新建安排。

for name, expected in zip(sys.argv[1::2], sys.argv[2::2]):
    assert len(expected) == 64 and hashlib.sha256(Path(name).read_bytes()).hexdigest() == expected, '包的SHA-256不匹配，停止恢复'

```

```

## 模型配置与故障

后台使用OpenAI兼容的`/v1/chat/completions`接口，要求支持图片和严格JSON Schema。本轮家庭设置支持保存私有`private/model.json`；也可在服务器环境设置`FAMILY_LLM_BASE_URL`和`FAMILY_LLM_MODEL`，需要鉴权时设置`FAMILY_LLM_API_KEY`。已有环境配置优先且不能在网页覆盖。可选`FAMILY_LLM_REASONING_EFFORT`只在模型支持时设置，不同服务能力不能由接口名称推定。密钥不在网页响应中回显或写入公开仓库。

`model.json`与`model.env`均为机器专属模型配置，不进入家庭数据备份；换机器或恢复家庭备份后需重新配置模型。资料、孩子和学习记录的恢复不依赖这些密钥。

已实测本机LM Studio、已安装Qwen视觉模型和`reasoning_effort=none`：虚构文字与试卷图片均返回可核对草稿。自有服务器可经SSH反向隧道访问本机回环模型端口；公网不得转发模型接口。模型主机须开机、联网且服务运行，冷开机自动恢复仍待实测。识别故障不会阻止原件或手动记录保存。当前语音服务为本机WhisperKit，已通过虚构中文录音及服务重启验收。

常见情况：未登录返回401；服务重启后旧表单令牌失效时刷新重试；图片类型不支持时可保留原件并手动记录；模型未完成、离线或草稿结构错误时保留原件，不把错误结果写入成绩。浏览器显示“已配置”不等于此刻模型在线。恢复数据前先停服务，在空目录校验备份，再由管理员切换，避免覆盖主库。


语音服务使用`FAMILY_ASR_URL`配置完整转写端点（例如`http://127.0.0.1:12346/v1/audio/transcriptions`），可选`FAMILY_ASR_API_KEY`、`FAMILY_ASR_MODEL`（默认base）。服务须支持multipart file/model/language/response_format并返回JSON text；本项目只发送此次选择的音频。转写文字可编辑，不自动保存。中文人名、数字和方言仍需人工听原音核对，示例通过不代表所有录音准确。

本机WhisperKit CLI可用`whisperkit-cli serve --model base --language zh --host 127.0.0.1 --port 12346`启动；首次需下载对应模型及tokenizer，不包含在源码包中。基础应用无第三方Python依赖，模型服务独立安装。WhisperKit本次版本不能直接解码浏览器WebM，因此应用用后台已安装的`ffmpeg`经管道转成WAV，每段最多3分钟；缺少ffmpeg时仍保存原件并提示改传WAV、M4A或OGG。其他格式转写取决于配置服务的解码支持。服务无内置鉴权时只能回环监听，并通过受限隧道由后台访问。

当前源码包含网页后台、独立Agent、只读CLI采集器及系统调度模板，配置步骤见[AGENT运行.md](AGENT运行.md)。需要自行配置CLI登录、授权群、模型端点和服务路径；不含其他家庭登录态、模型权重或运行实例。到期回看不依赖模型；需模型的资料失败后保留并定期重试。站内提醒已提供，微信/QQ对话入口和站外推送尚未提供。

## 家庭打印

网页勾选一份或多份已归档附件、上传资料，选择单双面，可为每份文件指定页码，直接点击“提交打印”；不要求先打开预览或额外勾选确认。默认每份文件1份、黑白，打印机和份数等放在更多设置中。提交时自动准备固定PDF并检查每份文件的页码，全部准备成功后逐份入队；部分入队成功后只重试未完成文件，保留原请求编号。需要检查内容时可自行打开原文件。

支持原PDF、JPEG和常见非交错8位PNG。页数读取需要安装Poppler的 `pdfinfo`，可用 `FAMILY_PRINT_PDFINFO` 指定路径。Word `.docx` 和PPT `.pptx` 转换需要另装LibreOffice，并在服务器环境中设置 `FAMILY_PRINT_SOFFICE=/usr/bin/soffice`。含宏、外部资源或不支持格式会拒绝转换，可下载原件或另存PDF后上传。Office仍通过已有转换链路生成PDF，排版可能与原软件不同；简化网页操作不代表已改为打印机端排版。

打印原件最多20MiB、PDF最多50MiB及200页，每次1至10份且最多500个页面副本。桥接指定A4、每面1页、适配纸张；双面用纸按每份单独进位估算。PDF页序与教材印刷页码分别理解。预览和原件留在私有目录，预览本身不会发送打印。

后台在自有服务器时，家中Mac通过已有SSH回环隧道领取确认后的任务，再交给本机CUPS。先在Mac系统设置中配置家庭打印机，用 `lpstat -p` 核对准确队列名；Bonjour发现不等于已配置或已授权。服务器私有 `private/打印机配置.json` 格式如下，所有字段必需，名称与能力按实际设备填写：

```json
{"printers":[{"name":"Example_Printer","label":"示例家庭打印机","color":false,"duplex":true}]}
```

在后台和家中桥接进程的私有环境中配置同一个随机 `FAMILY_PRINT_BRIDGE_TOKEN`（至少24字符），与网页会话令牌及登录密码分开。桥接只接受本机回环URL，不直接向公网传凭据。单次运行示例：

```sh
python3 print_bridge.py --url http://127.0.0.1:18765 --printer Example_Printer --once
```

URL应为已建立的SSH转发端口。按实际部署用系统任务定期执行这条命令；本源码不会自行选设备或安装定时桥接。持久日志默认保存在家中电脑 `~/.local/share/family-learning/print-bridge`。未配置队列时，网页仍可选择文件和下载原件，但不能提交打印。

同一请求重复提交沿用任务编号。发送前持久记录，断线、超时、崩溃后不盲目重打；结果不明需先核对本机队列和纸张。CUPS接收、CUPS报告完成及家长确认取纸为三个不同状态。仅未领取任务可在网页取消，已领取任务需在本机打印队列核对处理。家长确认取纸不会自动把学校作业标记完成。

打印PDF随 `private/print` 备份，任务随SQLite备份。恢复先验证归档哈希，再把未由家长确认的旧打印任务置为待核对，保留原状态与CUPS编号并撤销旧领取凭据，防止自动重放；这项保护会有意改变恢复数据库的哈希。切换恢复库前停止服务和桥接进程。打印机配置与桥接凭据属于部署配置，需私下另行保管。

反向代理应保留后台对打印PDF预览返回的 `SAMEORIGIN` 和 `frame-ancestors 'self'`，不要额外附加 `DENY` 阻止本页预览。其他页面保持禁止外部嵌入，所有静态资源、API和PDF均须经过同一身份认证。软件的模拟队列回归不能代替真实打印机出纸验收。

本轮已用虚构资料完成桌面与400 CSS像素窄屏检查：Three.js场景、暂停动效、记录新增与纠正重算能量、待办勾选、PDF预览、打印设置刷新保留、确认入队及取消。中文Word/PPT转换与认证入口已验证。实际手机和家庭打印机出纸仍待验收。

已用虚构资料通过真实本地模型、桌面与400 CSS像素浏览器的查询和来源跳转，包含离线输入保留、孩子切换、迟到的新来源、过期建议以及查询前后数据不变检查。真实手机操作仍须另行验收。


## 阅读营地与约定印章

从首页或学习进展打开阅读营地，也可从已有学校阅读事项建立关联草案。先约定书名、版本、范围、表达方式、完成条件和印章数；未知内容可留在草案，开始前须补齐书名、范围、表达方式和条件，并记录开始依据。开始后更改范围或方式需说明原因，孩子归属和原印章承诺锁定。

作品复用拍照、文件及录音入口；可直接保留原音，也可转写核对后提交文字。提交后为待确认，家长依据实际作品确认才获得印章；补充、暂停、恢复和旧作品均可追溯。AI反馈只查看本次已保存作品和可选原文片段，不代写作品、不发奖；没有原文时不核验篇目细节，模型离线仍能完成手动流程。学校原待办不会因阅读确认而自动关闭。

每项任务只有一笔约定奖项，重新提交或确认不重复发放；记录能量不计入可兑换印章。默认提案每项1枚，累计首次获得3枚点亮一个营灯纪念物，不消耗余额；活动兑换默认3枚，先由家长与孩子约定，再预留、实际兑现或取消释放。未占用奖项可撤销；已预留或兑现的奖项更正保留整笔账目并标为需家长处理，不形成负数或扣走新赚印章。请求结果不明时保留原操作编号，刷新后可核对。

首页孩子卡片可更正称呼、年级和班级，填写依据后保存并保留更正历史；陈旧表单会拒绝覆盖。孩子编号保持不变，当前成长记录与手动待办在同一事务同步称呼，旧来源的结构化归属按历史称呼解析，原文不改。历史称呼不得重新分配给另一位孩子。阅读任务与奖励使用稳定孩子标识，既有印章、作品、奖励及请求历史保留。阅读已绑定原件会校验孩子归属，成长记录入口同样检查此绑定；这不等于独立儿童权限隔离。阅读数据随SQLite整库和上传原件一起备份。恢复旧备份后，备份时间之后的真实奖励兑现须人工核对，不能由旧库推断。

已用虚构资料验证桌面及400 CSS像素窄屏的作品提交、家长确认、补充再确认、预留取消及兑现、丢失响应后的原编号重试、真实模型反馈和隔离恢复。浏览器录音测试使用模拟麦克风；实际孩子任务、现实奖励兑现及真实手机操作仍待家庭试用。

档案覆盖字段、历史称呼和更正历史保存在同一SQLite主库，随整库备份恢复。采集程序应以当前网页 `/api/state` 的孩子档案为准；家庭Markdown保留来源原文，直接改写旧姓名不是完整更正流程。`python3 test_profiles.py`使用虚构资料验证更名后的学习记录、复测关联、学校与手动待办、陪伴建议及印章保留，包含版本冲突、并发旧表单和原件归属检查。真实家庭档案未在验收中改动。


## 孩子的独立入口

家长首页的“孩子入口”可分别开启“每天的功课”、选择阅读任务，并生成一次性邀请。每日功课默认关闭，家长逐孩开启后，孩子可查看自己已安排的功课、行动要求、预计与实际用时及约定的休息时间；自己报一项功课、开始/暂停、补录用时或告诉家长完成到哪一步。历史日期只能更正已有安排，作息时间与收尾仍由家长安排。

孩子报“完成”或“需要帮助”会标为自述待核对，家长在“放学后”看到同一份记录，点“核对孩子的结果”后保存；只有家长确认完成才关闭原待办。家长从原清单直接勾选完成也会停止关联计时并保留用时。孩子不能更改已确认完成或搁置的功课，家长记录部分完成或需要帮助后仍可继续尝试；旧结果与核对来源保留在更正历史。每日功课授权不开放原始群消息、家长记录原件或其他孩子资料，关闭授权不删除时间账。

`python3 test_child_study.py` 与 `node test_child_study_ui.cjs`使用隔离虚构家庭检查权限、撤销竞争、父子核对、断线重试、冲突保留输入、备份与360／1440 CSS像素操作；实际手机和真实孩子使用仍待验收。孩子页优先展示今天的功课，可切换回阅读；无需模型即可操作。

阅读任务仍逐项分享。只有已经开始且被家长明确勾选的任务会出现在孩子的阅读营地；可查看阅读约定、当前作品和该项任务的实际印章，提交自己的文字、照片或录音，语音可选择转写后核对。孩子提交作品不会确认完成或发章，仍由家长核对。通用成长记录、群消息、家长核对备注与兄弟资料不在这个入口的范围。

邀请24小时内可用一次，登录7天后失效；家长可随时停用该孩子的全部邀请和登录，重新生成邀请会使旧的未使用邀请失效。邀请仅在生成时显示，不写入链接查询参数或浏览器持久存储。请在孩子自己的设备或没有家长登录态的独立浏览器使用；同一浏览器缓存着家长认证时，打开儿童入口不能撤销浏览器已有的家长权限。

本地开发入口为 `/child/`，与家长页面共用Python进程和SQLite；服务端只允许明确列出的儿童接口，所有资料归属根据儿童会话核对。独立入口当前覆盖功课、阅读与逐题分享的短引导，不表示已实现儿童全科教学、学校收件箱或完整的多角色后台。无模型可继续提交作品原件及文字；麦克风需要HTTPS或localhost及浏览器许可，实际手机与孩子试用仍需另行验收。

子路径部署必须保留儿童路径转发，例如将 `/family/child/` 代理到 `http://127.0.0.1:8765/child/`，不能代理到后台 `/`。这个子路径使用应用的儿童邀请认证，可单独取消家长BasicAuth；其余 `/family/` 路径继续完整保护。设置 `FAMILY_CHILD_COOKIE_PATH=/family/child/`、`FAMILY_CHILD_SECURE=1` 和 `FAMILY_CHILD_PUBLIC_URL=https://your-host.example/family/child/`，公开地址用于家长从SSH隧道管理时生成正确邀请。仅监听回环；不得将整个后台无认证暴露。Cookie为HttpOnly、SameSite=Strict，HTTPS部署要求Secure。

儿童邀请、会话哈希及作品归属随数据库备份；隔离恢复验证哈希后会清空旧邀请与登录，避免恢复已撤销的访问资格，家长需重新邀请。作品和已分享任务保留。恢复数据库因此会与备份中的字节哈希不同，原备份不被修改。

检查儿童入口：`python3 test_child_access.py` 验证服务端权限与提交来源；`node test_child_ui.cjs` 使用隔离虚构家庭与两个独立浏览器，检查分享、邀请、作品提交、家长确认、失败重试、撤销和360/400/1440布局。录音使用模拟麦克风，不能代替实际手机或孩子使用。浏览器依赖配置同前述 `test_startup_ui.cjs`。

## 学习对照回看

“学习进展”按已保存的同孩关联，集中展示原始尝试、订正、复测和补充观察。展开一条线索即可核对各次记录、分数、原件与直接关联的上一次记录，再点“记一次订正 / 复测”补记实际发生的尝试。新增记录仍沿用原表单，不要求先建立学习计划。

“学习这一步怎么完成的”是可选输入：本次帮助情况、与直接关联记录的材料关系、比较说明。空值保持未知；旧“独立复测”标签不自动证明独立完成，独立尝试不等于答对，相近新题不自动证明难度可比或已经掌握。日期差来自记录日期，同日或日期倒置会明确提示；缺失、跨孩或循环关联不能当成完整证据链。

这三个字段与原记录一起保存和更正，旧版本缺少字段时显示未知，随SQLite备份恢复；查询只使用实际填写的条件。旧客户端未提供新字段时保留已有值，家长明确清空才清空。不另建任务、自动打分或折算学习效果，复测记录获得的能量不因求助而扣减。`python3 test_followup.py`、`python3 test_growth.py`、`python3 test_backup.py`与`node test_learning_ui.cjs`使用虚构资料验证。本轮部署和浏览器验收状态见V1交付目标，真实学习效果仍需家庭实际尝试与后续回看。

## 消息来源状态与故障隔离

来源页分别显示上次成功读取记录、最近尝试、已读内容中的最新消息和历史增量登记。接入待验证或本次请求失败时保留旧资料，不把历史条数说成本轮新增，也不凭接口失败推断登录状态。每个来源的图片、文章、小程序和历史缺口可展开查看，并可转入对应孩子的待办清单；正文成功或零新增都不代表附件和全部历史已读。

采集状态JSON损坏、格式错误或读取失败时，API明确返回sync_error，来源页显示错误；已有家庭记录、阅读任务和手动跟进继续可用，不用空来源冒充没有消息。`python3 test_app.py`验证故障隔离，`node test_sources_ui.cjs`使用虚构资料检查来源状态、缺口、安全显示与窄屏操作。没有增加消息采集框架或网页直接控制聊天客户端的功能。
