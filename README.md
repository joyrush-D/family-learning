## 开发与协作

GitHub [main](https://github.com/joyrush-D/family-learning/tree/main) 是公开源码的统一基线。领取下一项工作前先同步最新 main；常规工作使用一个短期 `codex/<任务>` 分支，一个可独立验收的改动对应一个 PR，验证后及时合回 main，再开始下一项。不要从尚未合并的功能分支继续叠新功能，也不另设长期 develop 或工程师专属主线。

多个开发 Agent（Codex、Claude、Hermes）按 [AGENTS.md](AGENTS.md) 的“多 Agent 协作”分工：Codex 负责整体产品与交付统筹，并在家庭运行机负责发布与真实验收，Claude 作为核心系统技术负责人，统一负责记忆、教学目标拆解、Agent决策与反馈调整及功能合入，Hermes 负责错题照片识别专项；任务与状态见[协作看板](协作看板.md)。Claude Code 经 `CLAUDE.md` 读取同一份规则。

合入前核对代码差异、相关浏览器流程、暂存内容和完整公开历史；合入后确认提交已包含在 main，再清理对应功能分支。未合入工作和他人的未提交文件必须保留，不强推或改写共享历史。GitHub 源码更新和家庭部署是两件事，部署要单独核对版本与原主库，不能用开发数据覆盖家庭资料；参见[家庭实例升级与回退](AGENT运行.md#家庭实例升级与回退)。

每次交付同步维护本 README 的现行状态、[需求总账](V1交付目标.md)和受影响的 PRD/运行说明。GitHub About 保持“本地独立 Family Agent、家长主导、学校优先、局域网或认证公网访问、模型可配置、家庭试用”的定位；不用分支临时状态或未经验证的接入能力作项目宣传。

现行需求、优先级、主选与备选方案、未完成项和下一步统一维护在[V1交付目标与验收](V1交付目标.md)的“需求与方案总账”。PRD保留详细业务与验收规则，第三方文档记录具体借鉴和许可；日期较早的实现记录是历史证据。某条路线失败或等待外部条件不会取消对应产品需求，当前先做学校场景也不删去后续学习和成长范围。

时间管理是核心业务：把放学后的作业、活动和休息放在同一张时间账里，比较计划用时、实际用时和结果，逐步减少无效耗时并保护休息。用时变短不能单独算进步，还要看工作量、完成质量和所需帮助。

最新需求方向（2026-09-11）：家长是主要用户，负责计划审核、组织执行、与孩子沟通和补充反馈。当前阶段以学习为主；系统从学校要求、成绩和实际作答建立判断，通过家庭评估验证原因，再形成细化目标与计划，优先利用已有App、学习机和材料。每日有新反馈就及时提出调整建议，正式计划经家长确认后再修改；阶段复盘不阻止日常调整。记录可覆盖生活、兴趣和亲子关系，判断须保留来源、反证和更正，帮助选择孩子愿意接受且有效的方法。

本轮已新增持续学习目标、同日反馈汇合、候选原因和家长审核同任务调整，复用已有记录与作业计时。系统还会按规则算出每个词各方向的进展轨迹（改善/持平/退步、是否已达间隔后独立），连同上次确认计划的日期一起进入再评估：首末对照是观察线索，未作答不算退步；确认计划不等于执行，方法调整需结合确认后的实际可比反馈，再由家长审核。“按词回看”已显示各方向的首末对照；学习目标页的“孩子画像”按当前孩子汇总已确认时的判断、间隔独立及待回看方向，保留目标和日期范围。依据变化时标明旧判断待更新；若某条判断引用的原记录在确认后被更正或改归其他孩子，该判断会单独标出“失去原依据，待重新评估”，历史判断同样标注，下次分析不再沿用这些结论，正式计划仍须家长确认才变；点原记录可核对更正，或点“查看目标”回到对应范围。不同目标下相同词的证据分别展示，不任取一条当整体结论。画像还汇总本轮纳入的学业/外部来源记录、家长观察/转述和已确认计划，每类最多展示最近6条记录摘录，可直接打开原记录更正。来源名称或成绩不代表已核实，确认计划不代表已执行；家长确认过的评估与假设会按时间保留，被取代的判断进入后续再评估并在画像中标为历史；计划确认后才录入的考试或老师结果会单列提醒重新核对；从明确关联考试事项打开并保存的结果，会回流该事项已关联的同一孩子学习目标并使旧建议待重评。同科但未关联的事项不会被猜测挂入目标。完整方法效果、结构化考试比对、超出当前范围的长期推理与外部设备接口仍需实现或验证。直接与孩子语音访谈属于交互成熟后的条件能力，不是家长流程的前提。范围与验收见[PRD 2.07](PRD.md)和[V1交付目标](V1交付目标.md)；渐进式英语与语文学习设计参考Read Frog，完整增强流程仍在完善，Read Frog尚未接入。软件检查不表示消息来源、设备接口或教学效果已通过验收。

已过明确日期且未关闭的考试，会在“更多 → 成长助手”出现“记录考试结果”。点它进入现有学习记录表单，选择“成绩”或记录具体错处，核对实际日期后保存；再点“跟进待办”确认完成，或选择“不参加 / 不用做”。保存记录不自动关闭事项，关闭后提醒消失；记录保留原事项来源；如果该考试事项已明确关联学习目标，结果会进入这个目标的证据并提示重新评估，仍不会仅凭同科目猜测关联。打印、复习、订正等准备或后续工作不当作考试，模糊标题仍需核对。

老师更正或取消通知时，Agent会提出待核对变更。在“核对学校变更”中查看原事项和本次通知，核对新要求与截止后确认；沿用原任务，保留状态、反馈和历次原文。未提新截止时带入原截止供核对。取消未完成事项会转为“无需处理”并暂停计时；已完成等状态不重开。 已完成后又更正要求时，明确提示原完成记录只对应原要求，新要求是否需补做或已经完成仍待家长核对；后续新反馈或重新确认才更新该状态。普通通知的确认表单也能切换为更正/取消；找不到对应事项时留待选择，不按同科目猜。保存冲突可同处读取最新记录，填写保留，丢回执可重试。本功能见当前main，真实手机与家庭体验待验收。

在已保存学校消息的“原通知与原件”中，点“存为老师要求”，选择已确认的老师与适用范围，核对日期后保存。原文和群消息出处直接带入，可选取原文的一段，无需手填消息编号。该老师须已关联这个孩子和群；没有关联时可前往老师档案配置。保存后同处可查看、更正或撤回，重复归档不覆盖已有更正；失败保留填写，未确认保存可用原请求重试。有效要求沿用已有学习目标分析，不把要求当作孩子已经掌握，也不自动确认发布者身份或读取未读附件。此功能包含在alpha.5。

首次打开时，导航会立即显示已选页面，家庭记录读好后直接进入最后一次选择；问问助手与家庭设置使用相同规则。记录反馈在资料准备好后可用。数据读取失败可在原页点“重试读取”，保留页面选择；页面程序本身下载失败时仍可重新加载页面。导航不额外读取群消息或调用模型。

通知原件会显示当前自动取图是否启用、是否暂停、是否达到该图片的重试上限，以及已记录的超时或原图不可用原因；不会把旧失败当作仍在读取。补充可用原件后，同处的缺原图提示消失。打开通知只读已保存状态，不触发取图、重试或模型调用；文字同步与图片是否读清分别核对。

QQ非界面读取仍为首选。已核验LLBot 8.2.0提供Mac ARM命令行包，并通过不联网、不读取家庭资料的原生运行检查；它是独立QQ协议客户端，不是直接读取桌面QQ数据库。当前仍未证明同账号与日常桌面QQ稳定共存，不能因安装包可运行就启用采集。新版不同设备协议还有上游明确的未完成条件，具体取舍见[第三方方案](THIRD_PARTY.md)。

QQ本地数据库路线新增QQLore读取组件与ntdb_unwrap候选。已在Mac ARM完成虚构加密数据库的原生命令行读取、强制只读、错误密钥拒绝及独立进程读取已提交日志的检查；当前QQ数据库仅核对了文件头标记。腾讯官方QQ已恢复正常登录与聊天；本地数据库候选仍未成功解出真实消息，指定群结构、历史连续性与原件尚未验证，未启用。已修正候选取钥脚本的跨架构字符串定位问题，离线找到当前QQ版本中的相应函数；这仍不等于取得运行中的密钥，未改原客户端签名、未启用采集。qqcli-rs当前安装与解密流程仅支持Windows。本项目新增参考其使用流程的Mac实验性CLI，提供显式配置、诊断、指定群会话/历史/分页搜索和JSON输出。虚构加密QQ字段检查通过；真实配置诊断明确缺少密钥，未读取真实消息、未接入生产采集。用法见[Agent运行说明](AGENT运行.md#mac-qq本地数据库cli实验版)。具体边界见[第三方方案](THIRD_PARTY.md)。

QQ官方机器人也保留为非界面候选：腾讯SDK的普通群消息解析已通过虚构检查，使用机器人身份，不替换家长个人QQ登录；能否加入班级群并获得普通消息读取权限、实际消息和原件仍待验证。尚未启用，不能把机器人创建或连接成功当作学校消息已同步；身份映射、历史缺口及验收条件见[第三方方案](THIRD_PARTY.md)。

当前优先级：学校作业监督、课程进度与学校事务完成 → 课业提升 → 兴趣、体能与健康。首页“今天”直接列出未完成的课内作业；“日历”按日期查看待办、计划和课表。Inbox收集待办，Wish保存心愿，均可手动随时录入、选定日期转成计划。“作业执行”用于开始/暂停计时及记录结果，口头作业可补记。已确定截止的未完成事务逐日保留，逾期不消失；无日期留在收集箱核对。打开日历不采集群消息或调用模型。 已有事项和新事项统一归入“课内作业”或“待办事项”，今天与收集箱分组展示；打印、报名、回执、用品及作业入口核对归待办，具体抄写、阅读单、订正等归作业。尚未读清的学校资料保留待核对状态，不据此认定孩子有额外作业。“今天”也显示未定日期的未完成待办，明确安排到未来的事项仍在收集箱和对应日历中；完成、不参加和原记录保持。

界面以“今天、日历、收集箱”分工：今天只显示执行所需的信息，作业与待办的已确认数量和待核对通知分别标明；分组先列已确认事项，标题中的“待核对 N”可直接跳到首条待核对通知，避免通知较多时遮住当天功课。学校通知标题跳过纯“重要通知/温馨提醒”抬头，展示具体内容；完整原文保留。目标直接显示，勾选完成、作业计时、反馈和无需处理各有明确入口。心愿与历史在收集箱管理，课表导入与手机同步收在日历的“课表与设置”。手机可从分类链接快速跳到待办，桌面并排查看两类事项。

查看完整记录：今天的作业和待办标题旁分别有“所有作业”“所有待办”，一键打开收集箱的全部记录并定位分类，保留当前孩子筛选，包含其他日期、已完成及已搁置事项。收集箱也把“全部”放在首位；同一事务继续使用原编号和状态。

日历上方平铺周一至周日，每天直接显示作业、待办、计划和课表摘要；点击日期或事项，在同页下方查看当天完整目标、反馈、完成与打印入口。总览限制高度并保留全部事项，列表内可滚动查看；手机左右滑动查看整周，打开时定位选中日期；新建计划保存后定位到计划日期。读取失败保留重试，不把未读的一周说成没有安排。浏览器检查覆盖360/1440像素、跨孩子、保存失败重试和保存后重开；真实手机和家庭体验待验收。

在“日历 → 新建计划”的“重复”中选择每天、每个周末、每周指定日或每月指定日，填写起点与可选结束日期；同一天有多次时，点“同一天另一个时段”，最多8个时段。每月没有所选日期时跳过该月，不自动改期；时段不能重叠，时间不明可以留空。在某天的卡片点“处理本次”，可以确认完成、取消或改期，只改变所选日期的那个时段；原安排与历次说明可回看，其他日期照常。“编辑重复规则”只更新未单独处理的日期，已经单独改期、完成或取消的记录保留；已有逐次记录时不能将原循环改成单次，可另建单次安排。保存冲突时保留输入，点“读取最新状态”核对后再保存；保存结果不明时重试同一次，不能重复建项。也可点“说一句安排”，例如“从明天到月底，每天07:00到07:15、19:00到19:20共读”，模型会把起止日期、重复方式、指定星期/月日和每天多个时段带入同一张草稿卡，顶部先展示完整规则摘要。没说起点、周几或钟点时保留待填写，不把每周某日当作首次日期；表单中核对后才保存。常见相对日期与月初/月末依据本次北京时间和原话核对，无法明确的日期仍可手填。订阅同步排除原时段并保留改期后的单次安排，实际iPhone刷新待验收。

### 上传课表并加入日历

在“日历 → 导入 / 管理课表”选择孩子，上传 JPG、PNG、WebP 图片或粘贴课表文字，点击“识别课表”。系统使用已配置模型返回星期、节次、课程和待核对项；家长更正课程并填写适用日期，确认后才加入日历。也可直接手动填写，不依赖模型。已有照片可从“来源与附件 → 作为课表导入”继续，错误或超时会明确提示，成功保存的原件保留。

每个孩子同一日期显示一份当前学校课表；家长新导入的课表从生效日起覆盖旧学校课表，旧日期仍按原范围展示，截止后不会自动恢复过期旧课表。课外活动另建日历计划。已导入课表可更正；导入不代表当天作业完成。课表只保留已知节次，暂不生成手机日历中的上课钟点、自动识别单双周或处理 PDF/HEIC 图片。

验证涵盖手动导入、模型不可用、照片上传失败和重试、实际配置的豆包识别虚构课表图片、家长核对后入历，以及重复保存、跨孩子和生效日期；真实家庭课表内容及手机操作仍需试用核对。

后台提供 `calendar.ics`，沿用家长访问认证；部署者不能为订阅开放匿名访问。本轮接口与浏览器验证不代替真实 iPhone 的账号认证、刷新及使用验收。

## 第一版范围

软件交付、家庭试用和开源发布分别验收、并行推进。连续试用按实际启用后的第7、14、28天回看家长操作负担、孩子自主选择与延迟后的独立表现；等待真实反馈不阻塞仍可进行的开发。方案见[V1交付目标](V1交付目标.md)，这些检查点尚无实际结果。

- 家长通过文字、图片或文件提供信息；消息接入只处理明确指定的来源。
- 按孩子整理通知、截止时间和待办，保留原始出处，区分已整理与已完成。
- 记录成绩、考试范围、失分点和复测结果；区分作业完成与知识掌握。
- 记录孩子自述、父母观察和老师反馈，保留情境，不自动生成性格或心理诊断。
- 形成每周回顾，展示进步、困难和少量可执行建议，允许家长和孩子纠正记录。

同一个孩子在多个群收到同日完全相同的已读文字通知，且整理后的标题、目标与截止相同，会沿用原事项并补齐全部出处；已经完成、不参加、无需处理以及家长反馈都保留。之前在成长助手忽略的同一通知继续保持忽略。手动确认时会说明已沿用原决定，回执丢失后重试也不会重建。可以在原事项的详情中分别打开各群通知。不同日期、孩子、要求、拆分成果或未读附件不合并；仅有措辞相近的通知及已经存在的多个独立事项仍需核对，当前不自动删改历史事项。

学校待办勾选后立即显示“正在保存”，服务器确认后直接更新该事项及历史，保存失败则恢复原显示并提示重试。完成、撤销、不参加、恢复跟进和反馈进展共用同一保存接口，不再为了确认一次保存重新读取全部家庭资料；这些操作不调用 LLM。学校来源核对复用正在使用的数据库连接，修复后台提交保存时首页、日历和原通知读取相互等待而报错的问题；隔离并发检查验证读取与后台保存均成功，原来源和孩子权限继续核对。重复请求与陈旧页面冲突仍由后台核对。`node test_today_ui.cjs` 已按当前“今天 → 收集箱”流程更新，在隔离虚构家庭验证两类事项、完成/搁置/逾期分类、平铺孩子筛选、作业计时与结果回查、待核对通知、跨孩子、慢响应、保存失败、无需二次读取、重试、不参加与恢复、冲突及 360/1440 像素布局。家庭实际使用是否方便须另行验收。

## 学习目标与每日反馈

从“更多 → 学习目标与每日反馈”进入。选择孩子，建立一个阶段目标，写下看到的情况即可；不知道原因也可以。学校要求、教材与现有资源可选填，Agent负责安排小核对。已有学习建议确认后也会出现在这里。

同一页面可记录每天发生了什么、用时、卡点和孩子的感受，并标明家长观察、家长转述、老师反馈或平台报告。照片和报告保存为原件，本轮分析只读家长核对后的文字；可使用手机键盘语音输入。已有记录和原任务的作业结果也可汇入同一目标。

今天、日历或收集箱中保存的“反馈进展”，会自动汇入已明确关联的学习目标：包括目标的原计划任务、已关联该目标的学校作业及其计时结果。家长无需再抄写一次，在目标页“依据与每日反馈”查看原话和保存时间，也可继续补充。新的反馈或更正会使旧建议失效（清单勾选的固定状态文案除外），由既有独立Agent重评；正式计划仍须家长确认。未关联的任务不按同科目猜测归属，仍在原任务中保留。

每轮最多使用24条关联任务反馈、每条前1200字；先保留最近6条，再优先取已确认方案引用及原因判断的依据，其余按近期补齐。完整原话和更正历史保留在本地，页面说明超出范围；保存时间不冒充发生日期，完成、搁置与计划调整不作为掌握证据。关联错误或孩子归属无法核对时排除相关内容并提示。虚构家庭已验证保存失败重试、重开查回、引用、更正及跨孩子隔离；家庭实际使用仍待验收。

独立Agent沿用现有后台周期，按目标汇合新反馈，提出原因假设、核实步骤和下一步建议。 学校通知整理、单次学习建议和持续目标共用本次来源编号的选择范围，避免模型抄错引用导致整份建议无法保存；原文仍逐字核对，错误引用不猜配。 尚未确认计划时，页面只说明等待审核，不据此声称没有实际反馈。页面先显示“Agent建议的下一步”：具体怎么做、怎么问、记录什么；原因与证据可展开查看。家长只需反馈孩子原话或作答、实际帮助、用时和感受，不必先判断卡点。证据不足时安排一个小核对；提示后答对不作为独立掌握，新的独立尝试或疲倦反馈用于建议推进、减量、换方式或暂停。猜测和待执行的核对步骤与观察记录分开输入模型，建议不能充当已经发生的证据。家长点“确认”才创建或更新原任务；早期计划保存在根记录中的明确目标会带入当前编辑表单，修改回看日期继续沿用原任务，不要求重新建计划。保留原计划、暂缓、手动安排都可直接操作，模型不可用不影响记录和手动计划。更正依据后，旧评估会提示仅供历史参考，旧建议无法确认；模型运行中新增反馈也会使旧分析失效。没有增加调度服务或新的数据库表。

学习目标分析会同时参考同孩当天登记的其他功课、停止学习和睡前准备时间，以及当日日历中的安排。循环、单次改期和取消沿用日历原规则，已确认活动重叠只计算一次；同一份功课关联的日历学习时段不重复扣时，学校活动关联报名手续时仍保留活动时段。修改这些安排后旧建议需重新核对，到停止学习钟点也会失效，计时秒数变化不反复调用模型。模型看到分开的时段，不能把活动前的时间说成活动后剩余；睡前准备不能说成已入睡。最多提供24项其他功课、24项日历安排和24段已知时段，保留遗漏、未填钟点和资料读取失败提示；已知时段只是上限，不代表空闲或保证排得下。原地点、日历备注及其他孩子的安排不随本目标发送。仍用原表单，正式计划由家长确认。

老师的具体要求保存在目标的“学校要求 / 考试范围”，目标页可查看原文、出处和适用范围，更正保留历史并使旧建议失效。Agent可逐字引用这些要求作为安排依据，不能把要求当成孩子已经掌握或存在困难的证据。具体作业优先形成孩子听得懂的步骤和对应自查，保留必须、任选、示例与条件要求；家长提供的原文与群消息自动采集须分别核对。一次作文要求不会自动升级为老师长期偏好。

新群消息入库后，既有独立Agent会在筛选通知时识别具体教学要求及科目，选择同孩目标并自动关联原消息；无合适目标时建立学校学习目标，再调用学习模型生成辅导建议。沿用可配置的轻模型做筛选、主模型做教学分析，每轮总调用额度不增加，不依赖Codex代读、代写字段或触发分析。微信继续复用已可用的CLI；应用后台衔接状态与CLI本身的读取能力分别核对。当前来源优化重点是QQ群读取与桌面日常使用共存。

自动关联的原文、群来源、发布者及发送时间在目标页同屏可查；发布者身份和适用性待家长核对，不自动建立老师身份或长期偏好。每轮最多使用最近6条关联原消息，较早原文仍保存在学校通知中；新要求、更正、家长反馈或忽略要求会使旧建议失效并触发后续分析，正式计划仅在家长确认后变更。暂停目标保持暂停。未读图片、仅有成绩、行政通知和闲聊不作为具体教学要求自动建目标。

这一轮完成了目标持续跟进的软件闭环，尚不等于教学有效性和完整长期记忆验收。模型每次最多读取24条关联学习记录，先保留最近6条，再优先取原始记录、已确认方案依据及其明确关联的后续更正和反证；数量超限仍会遗漏，页面明确说明。当前计划内可展开“确认计划时的原文依据”，核对当时引用与现有原文；原文更正会提示变化，归属无法核对时隐藏引用内容。查看原记录或原任务不重绘整页，关闭后可继续原操作。原记录、修改历史和正式计划保留，正式调整仍由家长确认。工具和设备以家长填写的资源及报告关联，尚无讯飞、英语App的自动下发接口。真实iPhone、微信内浏览器、家庭持续使用和教学质量仍需验证。

验证：`python3 -m unittest test_goals test_agent test_agent_http`；`node test_goals_ui.cjs`（沿用本仓库Playwright环境变量）覆盖360/1440像素下创建、手动计划、断网重试、同任务调整、暂缓恢复、原记录入口及跨孩子隔离。模型结构验证用虚构数据，真实模型核验也仅发送虚构案例。

### 学校图片的待核对草稿

已授权学校消息关联可读图片后，独立Agent会在原有每轮最多3次模型调用中，取1次整理图片；页面打开只读取已准备的结果。打开事项的“原通知与原件”，可以同屏看原图、识别草稿和不确定项，再点“核对并填入学习记录”，更正文字、填写实际发生日期后保存。已有同来源记录直接回看，不重复建档；保存失败保留输入及同一次请求编号。

当前每条消息最多3张JPG、PNG或WebP，文字与图片合计20MiB。模型只整理所选孩子的内容；字母等级不会由程序换算为数值分数。其他文件、未下载原件和无法核对归属的资料保留缺口。失败最多自动尝试3次，原通知内可单独重试这一份；原件、关联或孩子档案变化后旧草稿不再使用。读取和识别均不代表作业完成、知识掌握或成绩已核实，家长保存后才成为学习记录。

只向家庭已配置的模型发送本次已关联图片和该条消息；不因打开页面重新采集或推理。真实豆包的虚构多人听写表验证保留目标行F、数字分数未知、排除邻行成绩；这不是对真实孩子的判断。浏览器验收与真实手机/家庭使用分开记录。

### 错题照片批量核对（网页与命令行）

r80起提供试卷错题的拍照核对流程。网页入口在“更多 → 试卷错题集”：选孩子、日期和可选科目后拍照或选已上传照片（每次1–3张），点“框出疑似错题”才调用家庭已配置视觉模型，在原图上叠框显示错题整题、手写区域和版面块，并逐题预填题号、题面、学生原答案和可见订正；家长在同屏改框选对应的转写文字、勾选保留或放弃某条、加备注，确认后每条错题保存为一条“学习进展”记录（来源“错题照片核对”、关联该照片原件），进入既有“起始→订正→复测”线索链。标注与保存分开，打开页面不调用模型，保存前一切都只是本页草稿；模型失败时照片选择和填写保留，可重试。

结果只代表家长核对过的错题：系统不判知识点、错因或掌握程度，不输出其他学生信息；模型不确定处单列，框选与转写都可能有误，必须逐题核对。记录不自动关联学习目标或任务，也不生成加练。未配置模型时手动“记录反馈”照常可用。

后端同时提供命令行 `python3 family_wrong_questions.py 照片1.jpg 照片2.png --subject 数学 --out 输出目录`（自动按3张分批，安装Pillow时另出画框预览），坐标按各自边长归一化到0..1000，网页按实际宽高还原。真实豆包对程序生成的虚构数学/语文小测验证：两页3道错题框精确率与召回率均为1.00，错误答案（含错字“窗处”）与订正（25、9、窗外）全部转写正确，并经真实HTTP全链路（标注→保存→state回查）和360/1440浏览器流程核对。真实作业照片、儿童手写、手机拍照质量与跨模型（含OpenRouter免费 inclusionai/ling-3.0-flash-vl:free）坐标质量仍待家庭环境验收；配置方式见[运行说明](AGENT运行.md)。

### 错题诊断、让孩子重做与间隔复测

保存错题本身不判断知识点。要看“卡在哪”，在“更多 → 学习目标与每日反馈”顶部展开“孩子画像 → 错题诊断 · 卡在哪”，按科目看已核对的错题数，分三步走：

- **诊断**：独立Agent在后台检查时，为有新错题、考试、复测或更正的科目准备诊断（每轮最多一次，排在学校与学习目标工作之后；同一版本最多尝试3次；其他同科目记录只作背景，不单独触发重跑）。家长也可随时点“诊断这科错题 / 结合最新记录重新诊断”。错题及其订正/复测不再逐条生成单独建议，统一由该科诊断理解。程序先确定性汇总该孩子该科目的错题、考试和同科目记录（订正/复测带上帮助程度与材料关系），模型只据这些原记录说出知识点、错误类型和可能的误解，并引用记录；编造的引用被丢弃，证据不足标“待验证”。每项按“有支持 / 待验证 / 有反证”显示，依据可点开原记录核对或更正；诊断后又有新错题、复测或更正时标“待重新诊断”，旧诊断保留为历史。
- **让孩子重做**：知识点下的“让孩子重做这道错题”把最近一道错题的题面和可见订正放进“一起学习”的短引导草稿（未分享、参考未核对）。家长核对后再分享；孩子重做时只得到一小步提示，拿不到可照抄的答案。同一道错题在分享前只保留一份草稿。
- **间隔复测**：“有支持”的知识点排在首次诊断后第7天复测；之后重新诊断时，该薄弱点若没有新的出错或复测记录，复测日保持不变，有新的就从那次诊断重新计7天。到期后独立Agent在“更多 → 助手跟进”提醒（不调用模型），画像标题旁显示“到期复测 N”。点“记录复测结果”会在原错题下新建一条“复测”记录，写明帮助程度和是否相近的新题，再点该科“重新诊断”。诊断规则只把独立完成、相近新题做对当作改善证据；知识点不再“有支持”后，提醒在下一轮撤回。提醒与复测都不代表永久掌握。

`/api/goals`只读返回各孩子的诊断与到期复测，不调用模型；`POST /api/diagnosis/run`与`POST /api/wrong/remediate`需家长口令，失败时原记录不受影响、可重试。检查：`python3 -m unittest test_diagnosis test_remediation test_agent`（含后台诊断每轮一次、无变化不调用、失败退避与暂停），`node test_diagnosis_ui.cjs`（360/1440、打桩模型，含后台诊断、失败重试、重做草稿去重、复测后重新诊断）。真实孩子的错题、复测效果与家庭使用待验收；FSRS排期与BKT掌握概率等教材单元（R17）给知识点稳定坐标后再接入，设计见[错题理解闭环架构](错题理解闭环-架构.md)。

### 单词分项核对

保存过核对后，在同一处的“按词回看”选择单词和目标义，即可横向比较各日期的七个方向、测试条件和材料。手机可在表格内左右滑动；点日期下的“查看原记录”补充或更正。查看历史不改正在填写的新核对，更正保存后保持面板展开。未测不算错，一次答对不代表稳定掌握；补充说明和原始作答仍需一并查看。

表格上方按固定规则列出各方向“最近一次结果”：只有在“间隔后复测”条件下、距上次同方向核对满 7 天的独立答对记为“间隔后独立答对”，其余都不视为稳定掌握；同一天多次结果不一时如实标注。距上次核对满 7 天、还没有间隔后独立表现的词会列为“可以间隔复测”的候选，仅供家长挑选：点一下把词、词义和“间隔后复测”条件填入下面的表单，家长仍要自己准备材料、核对并保存；不会建任务、改计划或调用模型，也不计算掌握率。

在英语学习目标的“把实际情况告诉Agent”中展开“单词分项核对”。家长填写一个词和本次词义，分别记录听英文选义/拼写、听中文拼写、看英文选义/读出、看中文说出/拼写；测了哪项记哪项，未测保持未知。可用现有App、学校材料或家长读题；纯听时不要让孩子看到本页英文，刚看过答案的答对记为提示后答对。在同一表单展开“只听声音来核对”，选择听英文选中文、听英文拼写或听中文拼英文；选择题使用原材料已有的中文选项。家长先准备，再把遮住答案的听题页交给孩子。播放只选浏览器标为本地的对应语言声音；没有声音或播放失败时可重试，也可继续使用原家长记录方式。

孩子提交回答后交回家长，点“家长核对并带回记录”，实际回答、选项、声音、重听次数及含播放/停顿的耗时会带回原表单；结果先留待核对，家长选择实际结果和帮助条件后保存。不会自动判发音或生成掌握率。同页已经听过本词时，后续答对不能填成首次独立表现；此前看过答案、页面重开后的练习情况仍需家长确认。保存和失败重试沿用同一目标、同一次请求，Agent继续汇合反馈提出建议。

手机/桌面浏览器流程已用虚构材料和模拟语音事件核验；真实iPhone、设备发音清晰度与孩子实际使用仍待验收。

结果保存到同一目标的原反馈，后台会据此提出调整，家长确认才修改计划。一次全对不自动记为稳定掌握，不同方向不互相代替；词表和测试条件未知时保留未知。验证沿用目标后端与360/1440浏览器检查，涵盖分项结果、未测、断网重试不重复和跨孩子隔离；真实孩子使用与教学效果另行验收。

## 当前使用顺序

1. 打开“今天”，先看今日作业，直接勾选完成、反馈或进入作业计时。尚未明确截止的作业也列出待核对；未来截止保留日期，未到计划日且无学校截止的家庭安排不会提前要求执行。通知里的“本周五”“下周一”按消息发送日换算，老师宣布的测验、听写等有日期的安排也会单独成为待办；一条通知含多个日期时各事项带各自日期并标为待核对，模型给出但原文无法换算的日期不采用。
2. 今天或收集箱点“＋记一件事”进入Inbox，心愿页点“＋记心愿”进入Wish；标题即可先保存，目标、截止、出处和建议可后补。两个家长分别录入，通过平铺的“全部孩子”和孩子姓名按钮翻看。Wish不是必须完成的任务，不自动计时、算逾期或发奖励。
3. 在Inbox或Wish点“转成计划”，选定日期并保存。仍是原事项，不另外复制；心愿从Wish移出，在Inbox与计划视图中可找回，日历对应日期可见。仅有截止的任务仍按截止规则保留待办。
4. 作业卡片依次显示简短标题、完成目标、操作建议。Agent整理新学校消息也使用这三个字段；目标只依据老师明确要求，可选方法不变成额外作业。旧的未处理学校通知也由独立Agent补整理：明确作业或事务自动收集为未完成任务，缺原件、条件或历史有效性待核对时说明缺口；成绩表列说明等参考资料不进入今天/收集箱的任务列表，仍可在成长助手查看原文。逐列解释检查表、向家长索取教材页或照片的纯资料求助，使用共享规则保留为参考；仅提到科目和页码不自动创建学习目标或加练，明确学校要求仍正常收集；“明天带来”等截止时间按原发送日核对，中文年月日和带起止钟点的单日选课/报名时间也能核对；省略年份只在消息发送月份内推定。未知或冲突时仅该条待核对，不阻塞同批有效通知；迟读到且已过截止的学校事项保留原日期、待核对是否已处理，不直接漏掉或安排今天补做。旧通知需结合历史原文判断，补整理使用已配置默认模型；新通知文字筛选沿用可选轻模型。旧通知每轮最多调用模型补整理1条，与新通知共用最多3次模型调用；规则可确认的参考说明无需额外模型调用，优先新数据，不覆盖家长已处理结果。同一资料自动重试最多3次。收集任务不代表报名、打印、作业完成、掌握或额外教学计划获批。家长可在“调整安排”编辑标题与目标，原文和更正历史保留。

收集箱收录所有未完成事务，计划筛选已安排日期的未完成事项；已完成与已搁置分开，不参加/无需处理不会计为完成。已逾期按截止日判断，未填截止时按计划日；日期不明、心愿和重复安排不计入，未完成项继续保留。

作业执行记录开始/暂停、预计和实际用时、结果与帮助。“更多 → 作业计时与结果”也可直接进入；完成不代表知识掌握。分类或无依据的日期不猜，计划、发布日期和学校截止分开。

验证：`python3 -m unittest test_agenda test_agent test_agent_http test_goals test_calendar test_calendar_ics`、`python3 test_task_focus.py`、`node --test test_calendar_ui.js`。覆盖心愿隔离、同ID转计划、重复收集重试、跨孩子、目标与建议分开、今日作业优先，以及此前日历与保存保护。主流程浏览器检查使用 `node test_today_ui.cjs`、`node test_task_focus_ui.cjs` 和 `node test_calendar_ui.js --browser`（沿用 `PLAYWRIGHT_MODULE`、`PLAYWRIGHT_CHANNEL`）；日历浏览器检查走“课表与设置 → 同步到手机”。后两项分别覆盖安排/冲突和订阅入口，不代表完整日历规划或真实手机认证通过。其他仍引用旧首页或旧导航的脚本须随对应流程修复，不能计入新版验收；本轮未把旧脚本批量替换后宣称全部通过。

## 老师档案

老师档案中已保存的“明确要求”，会自动进入同一孩子、同一科目的学习目标，显示在“本次学校要求”原区域，可直接回到老师记录更正。模型每轮最多参考6条并标明遗漏；家长理解、表扬别人和公开网页摘录不作为这类要求。更正、撤回或归档后，旧建议需重评，已确认计划保留至家长重新审核；老师要求不等于孩子的实际表现，也不保证仍适用于今天。记录和目标查看无需重新读取群消息。

从“更多 → 老师档案”添加任课老师，记录明确要求、表扬了什么行为和老师说出的理由；家长的理解单独标成待核对。涉及其他学生时只记录行为，不建他人姓名档案。“问问助手”可按所选孩子和明确日期引用这些记录，打开对应老师档案。没有记录就保持未知，不推断老师固定偏好。

每位老师可填写一个已确认的公开教学或职业网页，现有Agent每七天检查一次并缓存摘录，失败保留上次成功内容；看页面不会触发外部更新。仅支持无需登录的HTTPS文字页面，拒绝内网和重定向，每次最多比较前6000个可读字符；网页变化待家长核对，不自动改变偏好。未确认身份与链接时不开始检索。当前群消息自动识别老师与归档表扬尚未接入，消息自动归档流程另行验收。

## 每家独立运行与家庭盒子方向

默认部署方向是单机家庭中心：一台家庭电脑同时运行网页服务端、Family Agent、SQLite主库、附件、已授权来源的CLI读取和本地打印桥。手机与其他电脑通过认证网页访问家庭中心；“服务端”是这台家庭电脑承担的角色，不要求另买云服务器。家庭中心休眠、关机或退出所需登录会话时，相应服务可能中断；手机访问、HTTPS、真实连接器及冷启动须单独验收。

现有代码已提供同机运行与Mac服务配置基础；当前试用实例的网页、Agent、SQLite主库及附件已在一台家庭电脑运行，原远端仅保留可选的认证HTTPS转发，旧后台已停并隔离。迁移使用停止旧写入后生成的新备份，已核对业务数据、原件、两个入口到达同一实例、日历UID及模型实际调用；选定打印机设备配置随备份保留，桥接token仍需单独配置。当前手机入口仍依赖远端认证HTTPS转发，实际手机、出纸、冷开机和全新Mac仍待验收。邮件属于未来可选来源，须另行确认账号与范围，尚未接通。

交付主体是可独立安装、启动与持续运行的成长陪伴 Agent，包含运行服务、家庭数据、工具及手机/电脑网页入口。Agent根据目标和新信息形成行动，在授权范围执行、保存结果，并依据反馈调整后续安排；网页负责交互，Skill/CLI负责接入。Hermes或其他Agent Harness只是内部候选实现，不能要求家庭另装某个聊天宿主再挂插件才能完成核心流程。LLM可配置更换，框架选择不能绑定家庭数据或业务流程；两种豆包已在同一虚构家庭核对网页查询、指南和独立后台跟进，切换保留业务资料；教学质量边界及真实家庭验收仍保留，详见[V1交付目标](V1交付目标.md)。同一份源码先能在普通电脑或自有服务器运行，未来可预装到家庭计算盒子。每家独立初始化自己的档案、模型配置、微信/QQ登录和授权群，不附带任何其他家庭资料或账号。

盒子运行应用与盒子运行全部模型是两项能力。先支持本地保存和基础操作，再由家庭选择适用的本地模型或外部API；外部API会接收本次调用所需资料，不能宣称此模式数据从不离开盒子。硬件要求依据实际照片理解、中文转写、问答质量、等待时间和整机恢复测试确定，目前没有验证过的整机型号或一键装机方案。

成本控制列入交付验收：规则和CLI能完成的工作不调用模型，明确小任务使用通过质量验证的轻模型，复杂规划与教学判断使用合适的较强模型；按任务限制上下文、输出和总尝试次数，记录实际用量并说明升级原因。当前已有统一模型、局部上下文与每轮调用限制，同一资料指纹自动尝试共三次后暂停，网页可明确重试；家庭设置现可展开近30天模型用量，按任务和模型查看调用次数、已报告token及等待时间，未知用量单独列出；仅统计启用记录后的请求，不含语音转写。现可为纯文字学校通知筛选配置同一服务的可选轻模型，其余任务继续使用默认模型；不另用模型分派，失败不自动升级，清空轻模型即恢复单模型。学校通知筛选因结构化结果较大单独允许最多6000输出token，其余任务保持3000；次数上限未增加。模型同时给出互相矛盾的新增/变更关系时保留为家长待核对，不丢整批原资料。两种实际豆包模型已用同一组虚构通知核对，并在同一虚构家庭按等价资料验证查询、指南与后台提案、批准、反馈和到期回看。较强模型在本案遵守休息并根据后续意愿调整；轻模型数学提示出现整除方向措辞歧义，仍只用于通知筛选，不由运行成功推导教学合格或费用节省。具体约束见[PRD](PRD.md)。

模型质量按具体任务核对：孩子表示累了或想停止时，学习提案应先结束本次，不把核对旧题当成不占用时间。后续依据实际完成、帮助程度与孩子意愿决定维持、缩小、换方法或暂停；维持时也要说明尚待核对的表现。教学指南的帮助步骤要求给出一句本题可用的具体提示，模型草稿仍须家长核对。两模型的接口可替换，不代表任意模型在数学、图片或语音上质量相同。

当前独立安装需配置认证、系统定时器、消息CLI、模型/转写及打印能力。已提供独立Agent进程与CLI采集器，由操作系统定时运行、提前保存建议和站内提醒，不依赖Codex或网页访问。安装和恢复见[独立运行Agent](AGENT运行.md)。现有微信读取和语音/打印链路仍有系统及设备依赖。微信复用已有CLI；Mac后台权限归属不清时，现可构建以产品命名的采集入口，隔离原生进程检查通过，但构建不代表授权或持续读取恢复，操作见[运行说明](AGENT运行.md)。本轮原微信后台在解锁后的自然轮次完成三个来源读取及六条新增入库处理，锁屏后持续性仍待验证。QQ优先满足桌面共存，允许由独立Family Agent调用Computer Use作保底；Cua在开发宿主已读到指定群，独立系统宿主实测缺少辅助功能与录屏授权，尚未恢复持续采集。读取班级群与微信对话入口分别验证，未登录或未读取的内容显示缺口。不能据此承诺任意小盒子接电即可全功能运行。

## 一起学习：目标、指南和真实尝试

打开“学习进展 → 新建学习任务”，选择孩子，填写这次题目或学习内容；不必先创建学习记录，也可从已有记录继续。题目原件须逐件选择是否分享，参考为可选项，不默认分享原记录备注或附件。已分享材料保持原样，发现错误时先停止分享，再重新准备。

任务保存后留在同一个工作区：

1. **准备教学指南**：写本次目标与可观察表现，可自行保存，也可让已配置的模型起草。指南写清先做什么、问什么、卡住怎样提示、如何收尾和下次怎样再试；模型草稿须家长核对确认。没有模型也能手写使用。
2. **让孩子尝试**：家长可选择把确认后的目标与观察点给孩子看；完整家长指南和未确认草稿不进入儿童接口。孩子从自己的入口用文字、照片或语音表达思路，按需取一个提示，再次表达；可求助、暂停或跳过。
3. **记这次反馈**：工作区直接补充关联的实际观察，保存后回到当前任务；生成或调整家长指南时会读取本题相关观察，实际尝试不覆盖。帮助情况保留孩子自述，并记录该次表达前已有的系统提示数量。尚无原始记录或孩子尝试时，先收集真实表现。
4. **安排再试**：同处打开日历，商量日期时间后保存或取消，返回当前任务；也可准备相近新题。当前日历仍是独立事件，不承诺能从已保存的日历事项自动反向打开教学任务。

学习页首先显示当前任务和已有记录的继续入口，完整成绩、原始记录和成长背景收在可展开的档案中；引用跳转会自动展开目标记录。手机用单列，桌面并排展示具体引导步骤，主要操作留在任务内。

指南是一份可修改的建议，不代表孩子已经接受教学或掌握知识，不自动完成学校作业或计奖。实际尝试保存当时对应的确认指南版本；改目标不会重写旧记录。任务更新、暂停或停止分享后，迟到的模型草稿不会成为最新指南。只向本家配置的模型发送当前题目、参考、有关尝试、本次目标及下述有限家长观察；外部模型适用条件须按实际年龄、地区和服务核对。

家长指南读取直接关联到本题原始记录或本题各次尝试的同孩“补充观察”，排除儿童短引导尝试来源，按记录日期、编号从新到旧最多取6条，另提示更早观察数量。观察原件不读取并明确提示；这些观察不进入孩子提示请求。本次观察依据变化会使进行中或待确认的旧草稿失效，可立即重新生成，确认时再次核对；已确认指南与旧尝试保留。本轮反馈接入已通过隔离后端、LLM边界及360／1440浏览器检查；同一豆包模型的两个虚构情境已核对反馈调整与暂停。上述检查不代表广泛教学质量或教育效果已经验证。

孩子提示要求先有自己的尝试，并有可核对材料。得到一个提示后，先说说新的想法或还有哪一步没懂，再请求下一步提示；不要求答对。暂停再继续、刷新或家长改指南不会重复生成同一次尝试的提示，已保存的提示可在历史中回看。保存新表达后，主区域不把上一次提示当成本次回应。模型请求期间可点独立的“暂停”或“找家长帮忙”，未保存输入仍保留。

缺少参考、模型失败或看不清时继续允许表达与手动记录；失败或停止的请求可按需重试。语音转写须核对，PDF等暂不能直接送入提示模型。模型报告参考冲突或无法核对时不展示解题提示，但这不构成正确性保证。

教学流程借鉴[EEF数学指南](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/maths-ks-2-3/)的解释思路与逐步减少帮助、[EEF读写指南](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/literacy-ks2)的讨论与表达，以及[IES学习与复习指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)的间隔回看和提取练习。它们支持设计思路，不证明本应用已提高成绩；不预设通用的固定复习天数。真实手机、孩子意愿和延迟后的独立表现另行试用。

检查入口为 `python3 test_guided.py`、`python3 test_llm.py`、`node test_guided_ui.cjs` 和 `node test_learning_ui.cjs`；隔离虚构样本、实际模型调用、部署与真实家庭效果分别记录。

### 记课堂教到哪里

在“更多 → 学习任务与进展 → 记课程进度”填写科目、教材/单元或课次，以及老师讲到哪里、具体要求和适用日期。学校通知的“留作学习记录”也能选择课程进度。教材版本、授课日期不清楚时在正文注明，原件仍可上传核对。

课堂进度与孩子实际表现分别标识；可从同一线索“补充观察”记下孩子的原话、作答与帮助。已有同科目的持续学习目标会自动读取这名孩子的课程背景及明确关联的反馈；课程背景最多6条，优先保留已审引用，其余取近的，个人反馈沿用24条窗口，遗漏可回看或明确关联。没有同科目目标时先保留记录，不自动布置新练习。

同科目不代表教材或单元一定适用，课堂讲过也不代表孩子已经掌握。更正课程原记录后，目标里的旧建议须重新核对，已确认计划仍保留。软件及虚构模型案例检查通过后用于家庭试用，课程自动覆盖、真实手机体验与教育效果仍需另验收。

### 将学校反馈接到学习记录

学校信息或行动清单中的“留作学习记录”打开同一个记录表单，带入孩子、原出处及待核对材料；核对实际日期和内容后保存。相同孩子、相同出处已有学习记录时，继续原线索并追加观察，不重复新建。事项完成状态与学习记录分别保留，孩子的解释不能自动证明作业已经完成。

一般作业反馈显示原情况和后续观察；已有成绩、订正或复测的线索才优先展示订正与复测流程。群图片当前不会自动识图入学习档案：需要取得可读原件，沿用上传、图文草稿及人工核对流程。未读图片和家长转述必须标明，不据此判定缺交、未做或已掌握。

公开代码已支持用户文件上传；教材来源索引、版本匹配与内容解析仍为规划。第三方教材全文、扫描图、完整提取文本等默认不随开源仓库分发；GitHub可访问不代表已核实教材内容的再分发授权。只读取本轮所需版本与章节，不全量克隆教材库。

## 运行与数据

Python 3.10及以上，基础后台无需第三方Python依赖。在应用目录运行 `python3 app.py`，打开 `http://127.0.0.1:8765`；空家庭直接进入网页初始化。命令行首次初始化仍可使用 `python3 init_family.py`，交互填写孩子称呼和年级；已有家庭资料会拒绝初始化。实际姓名建议交互输入，避免进入终端历史。

### 新家庭与设置

新 Mac mini 或其他主机先安装并启动同一份应用；本项目负责应用内配置，不负责安装微信、QQ、模型应用或迁移个人登录态。

1. 空家庭启动后自动进入“家庭设置”，填写一个或多个孩子的称呼、年级、班级；已有家庭可从页面顶部进入该入口。添加和更正沿用稳定孩子编号，既有记录不会因改名而另建一个孩子。
2. 在消息来源中填写平台、群名称、已核对的群号或 chatroom ID、归属孩子，并分别启用或停用；一个孩子可绑定多个群。本轮需填写明确 ID，没有自动枚举群列表。新微信来源从本机可读取记录起点分批读取，界面保存配置不表示全部历史已覆盖；旧来源保持已有游标。已有历史来源不能通过改名或改绑转给另一个孩子，停用保留历史与游标。QQ 原生历史未就绪时继续显示缺口。
3. 模型可稍后配置。设置页保存家庭自己的服务地址、模型名与可选密钥到私有配置；已有服务器环境变量优先，不把已有密钥回显到浏览器或改写为另一份。保存后可点“检查已保存的连接”，只发送固定测试文字，验证模型响应及要求的返回格式；图片、语音能力另行验证。“更多模型选项”可填写轻模型，仅用于文字通知筛选，与默认模型共用地址、密钥和推理参数；可单独检查已保存的轻模型，留空则使用默认模型。保存配置不代表模型调用或群读取已通过。
4. 微信／QQ 在消息所在电脑登录，按 [AGENT运行.md](AGENT运行.md)配置实际可用的 CLI 和定时采集。页面显示实际连接结果及最近成功读取；没接好也可先手动记事、上传资料和安排功课。

首次初始化、添加孩子、来源及模型配置已通过隔离 API 和 360／1440 CSS 像素浏览器流程验证，并通过空家庭源码包启动检查；实际手机、全新 Mac 整机和第三方登录兼容仍需实测。不要在已有家庭目录重复运行初始化或用示例覆盖私有配置。

### 新 Mac 的应用运行配置

已有 Python 和本应用源码后，在应用目录运行 `python3 configure_mac.py` 只看配置计划；需要应用随当前用户登录运行时，执行 `python3 configure_mac.py --install`。该命令仅安装本应用的网页、每分钟 Agent 检查、保持运行并每轮间隔 5 分钟采集的三个登录服务，并创建私有采集配置；不安装或登录微信、QQ、CLI或模型。未发现消息 CLI 时不加载采集服务，仍可打开网页填写家庭资料和手动记录。

只在家中使用时，手机和电脑连接同一家庭局域网，直接访问家庭电脑即可，不需要服务器转发或公网域名。新安装可用 `python3 configure_mac.py --install --mobile-url http://192.168.50.2:8765`；示例IP须换成家庭电脑的实际内网地址，端口须与本机应用一致。要在家里用浏览器录音和 iPhone 日历订阅，改用 `--mobile-url https://192.168.50.2:8443`：安装器生成家庭证书，手机装一次证书后同一账号登录。安装器生成私有家长账号和口令，保持登录180天；孩子仍用独立邀请。已有家庭按[局域网直连步骤](AGENT运行.md#仅本机局域网访问)修改原部署，不重新安装或迁移数据。此能力为alpha.5之后的main增量。需要HTTPS时仍可按下一节配置，但家庭局域网使用不以它为前提。

若刚才在终端手动运行了本应用的 `python3 app.py`，先在原终端按 Ctrl+C 停止它，再安装登录服务，避免占用同一端口。也可以直接安装服务，无需先手动启动；已有家庭服务按升级流程维护，不重复安装。

微信 CLI 默认从当前 PATH 查找，也可用 `--wechat-cli` 指定已有可执行文件；`--qq-cli` 指定已有兼容只读 Python 脚本。只想生成文件供检查，可用 `--output-dir` 指向一个不存在的新目录。发现已有家庭服务、采集配置或端口占用时拒绝安装，不能用它覆盖原有家庭部署；Mac 休眠、关机或退出登录时服务不会持续工作。更多运行与恢复说明见[AGENT运行.md](AGENT运行.md)。

`python3 test_configure_mac.py` 已在隔离环境检查路径、文件权限、计划生成、拒绝覆盖与安装失败撤销；未据此宣称在一台全新 Mac 完成实际服务安装或冷开机恢复。

网页读取本地家庭Markdown台账；网页新增记录、编辑历史和事项状态保存于 `private/family.sqlite3`。消息采集与整理按独立的例行任务提前保存，网页刷新只读取已保存资料，不触发微信或QQ采集或模型调用。记录实际完成状态时须补充依据。SQLite与私有附件一起备份，避免丢失。

页面脚本、样式和Three.js在服务启动时预先打包/压缩，保留服务器内存缓存；浏览器保存静态资源，每次访问校验ETag，内容未变返回304，不再下载正文。未使用内容版本的资源URL每次校验，代码更新后自动重建并下发新版。`Cache-Control: private, no-cache`允许私有缓存并要求校验，并非禁止存储。较大的JSON响应也使用压缩传输；家庭数据接口、原件和孩子会话继续`no-store`，读取最新保存内容，不会用定时快照覆盖刚提交的记录。基础运行无需增加缓存服务。用`python3 test_http_cache.py`检查压缩、版本更新、访问边界与数据新鲜度。

每条成长记录可展开“查看更正历史”，按需读取当前版本和全部已留存旧版本；可比较分数、说明、日期、当时称呼、来源与原件关联。旧版本不作为新进展，也不会自动覆盖当前记录。损坏快照和缺失原件会单独提示，其他版本仍可查看；未保留附件字段的旧版本不据此认定从未有原图。历史原件只在点击后打开，读取失败可重试。此流程复用现有修订表，随同主库备份恢复；`python3 test_app.py`包含只读、历史顺序、原件缺口及访问边界检查。

来源整理按独立会话进行：一个孩子可以对应多个已授权群，各群分别维护采集游标、最近成功读取时间和内容缺口。同一通知跨群出现时，应合并事项并保留多个来源；主要群用于突出展示，不得因此遗漏其他授权群。班级群信息读取不依赖微信对话机器人，未读附件和未覆盖历史继续单独记录。

未配置局域网入口时，默认仅监听本机回环地址；显式配置内网HTTP入口后开放局域网监听，仍核验家长账号，拒绝公网来源和代理转发。局域网HTTP的浏览器内录音和手机日历订阅入口受HTTPS要求限制，可先使用手机键盘语音输入、上传照片或已有录音；需要这两项时改用 `--mobile-url https://内网IP:8443`，应用用系统 `openssl` 签发家庭自己的证书并在第二个端口直接提供 HTTPS，手机安装一次 `private/tls/ca.crt`（或打开该地址下的 `/family-ca.crt`）后录音与日历订阅即可使用，步骤见[局域网 HTTPS](AGENT运行.md#局域网-https家庭证书main-增量真实-iphone-待验收)。可选单机手机HTTPS访问使用 Tailscale Serve 提供家庭私网内的 HTTPS，应用通过私有 access.json 核验家长口令，孩子另用自己的邀请；手机须能访问该 tailnet。旧的 FAMILY_HOST/FAMILY_USER 身份头模式在未配置 access.json 时保持兼容，新家庭按上面的单机入口步骤配置。本项目不启用 Funnel。

已支持网页上传照片、PDF、办公文件、文本与语音原件，单文件最多20MiB；可关联成长记录，未关联文件保留在待整理资料。支持浏览器录音（需HTTPS或localhost及麦克风权限），上传失败可重试。配置模型后，文字与JPEG/PNG/WebP图片可生成待核对草稿；每次最多3张且合计不超过20MiB。草稿不会自动入档，需填入表单、人工纠正再保存。配置语音服务后，录音可转为可编辑文字，再整理草稿。PDF、办公文件和HEIC目前只保留原件，尚未自动解析。可用手机键盘语音输入文字后整理；教材支持仍为规划。

2026-09-10 的 main 增量修复了成绩表整理的孩子归属：先选择孩子，后台从档案取得称呼并要求只取对应行；找不到或无法区分时留空待核对。切换孩子会撤下旧草稿及其未被手动修改的填充值，保留家长填写内容，迟到的识别结果也不能填入。两次实际豆包调用在虚构排版成绩表上分别验证了正确取行与缺席留空，原件保留、显式保存及360/1440像素表单已核验；真实照片、手写识别和手机操作仍需另行验证。此增量晚于 alpha.3，已包含在 alpha.4 源码标签中。

## 自有服务器部署

可将同一程序部署到自有Linux服务器，以systemd运行，保持监听127.0.0.1:8765，通过SSH隧道访问：`ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 user@server`。无需增加框架或数据库服务。仅监听回环不隔离服务器同机用户，应使用受信任的服务器账号环境。

迁移时先停止旧实例写入，用SQLite backup生成一致副本；服务器数据库成为唯一主库。消息采集电脑向主库提交已授权消息并由服务器确认游标；旧文件同步只上传原有台账、状态及必要附件，不以本地数据库覆盖主库。已验证认证HTTPS反向代理入口及桌面读写；真实手机操作尚待验收。现有微信CLI负责指定群的信息读取，未来微信对话Agent的接入另行验证。

待办支持手动新建、勾选确认完成、取消勾选恢复跟进、按孩子和状态筛选，以及追加进展反馈。每条未完成事项另有“不参加 / 不用做”入口：明确选择“不参加”或“无需处理”后移到“已搁置”，可以恢复跟进，说明可留空，决定本身仍记入历史。搁置不代表完成，不增加学习记录或奖励，也不会向学校发送消息。关联功课停止计时并保留已记用时，不再计入剩余工作；日历保留学校原安排，另标家庭决定，并仅释放该孩子的对应可用时间。勾选只记录家长的确认，不代表系统核实了实际完成。事项历次状态与说明保存在task_history，旧状态会在首次更新时保留。手机采用底部导航和底部反馈表单，桌面保留侧栏。

## 从学习反馈到下一步

在“成长助手”查看有依据的学习建议，点“核对并安排”，确认要做的小动作、预计投入和回看日；也可“暂不考虑”。安排后可从同一张卡跟进待办、补充实际进展或改天回看。回看日是家庭约定，不替代学校截止；建议与家长确认内容分别保留。

实际用时和结果仍在“放学后”记录；新的观察可用“补充实际进展”关联原记录。后台结合这次反馈与前次已确认方案提出下一步，家长核对后再安排。完成一次动作不自动等于掌握，也不自动发奖。无新资料不重复规划，到期提醒由规则生成，打开网页只读取已保存结果。每轮每孩最多一次学习规划请求，新记录不因当天已有建议而被跳过，模型故障保留手动入口。

## 事项的下一步与回看

借鉴 [GTD 的澄清与组织流程](https://gettingthingsdone.com/what-is-gtd/)，沿用已有事项编号管理家庭决定。卡片直接展示要求、下一步、原截止和当前反馈；出处与历次记录按需展开。日历准备备注、阅读分享方式及完成条件、放学后功课的原要求同样直接可见，避免开始行动前逐个找详情。

在“安排下一步”中写一个具体动作，再选择“下一步可以做”“等待别人／条件”或“改天处理／以后再说”。等待需填写对象或条件，可约定回看日期；改天也可不定日期。到回看日期后，未关闭事项重新出现在“下一步”和首页“今天回看”，供家庭决定是否继续推进。原学校截止时间与日历不会被推迟或覆盖；原截止恰好在今天的事项仍显示在首页。已加入放学后计划的功课和计时需在原处调整，本入口不擅自停止或重排它们。

这不是第二套任务库，也不是新的完成状态。完成仍需确认，暂不参加或无需处理仍进入“已搁置”；这些安排不增加成长记录或奖励。问答证据包含家庭安排与等待条件。页面到期回看不代表已发送微信或手机通知；每周完整 GTD 回顾及多步骤项目依赖尚未实现。

本轮用虚构家庭检查多端关键内容可见、保存重试、并发更正、等待／改天后回看、权限边界与备份恢复；实际手机和家庭长期效果仍需试用。

## 家长今日首页

首页按孩子展示当天课表、明确日期的待办及日历安排，可以直接勾选、补充进展、打开“记学习”。旧日期只提示核对，日期不明和未来事项在其它待办；课表或消息未读时保留缺口说明。阅读回看与家长待确认作品单独标明。探索星球移至成长记录里的主动入口，进入家长首页不再加载Three.js。每日安排复用已有日历和同一待办状态，不产生第二套任务。`python3 test_today.py`及`node test_today_ui.cjs`使用虚构资料核对聚合、数据新鲜度与桌面/窄屏操作；实际手机与孩子参与仍待家庭试用。

## 放学后的时间管理（家庭试用已部署）

本轮增加家长与孩子共同使用的每日时间页：放学后说清今天有哪些功课，复用已有待办或手动补充，给每项一个预计分钟数。晚饭、运动和课外活动继续放在原日历；按家庭明确设置的停止学习时间查看可用时间，不预填成已经同意的作息。

做一项时开始，休息或离开时暂停，结束后选择“完成”“做了一部分”或“需要帮助”，可补充帮助和卡点；忘记计时可以补录并标为补录。暂停不改变作业完成状态；保存本次结果时，计划、已记录用时、结果和说明归档为普通学习记录，可以从“学习记录 / 后续尝试”继续跟进。近7天按实际有记录的日期回看，不把漏记当零分钟，也不做效率分或兄弟排名。

关闭页面不会自动暂停。较早日期仍在运行的计时可打开原日期核对；跨日、异常长计时等显示用时待核对，不纳入确定的实际分钟。从备份恢复时，原先运行中的计时暂停并标为待核对，保留已保存的用时，需按实际情况补录后再继续，不把停机期间自动算作学习。

手动记录、计时和反馈不依赖LLM，手机键盘语音可代替打字。在“更多 → 作业计时与结果”选择孩子和日期，点“用登记本 / 语音报功课”，可贴原话、拍登记本或上传照片/录音，并单独补充孩子对缩写的解释。点“整理成作业”后逐项核对短标题与完成目标，再加入这天的清单；模型不可用时点“直接填写一项”。原件、原话与解释保留在该功课，录音转写先听原音核对。未保存草稿只在当前页面保留，离开前会提示。家长可协同记录，也可逐孩开启“每天的功课”，让孩子从独立入口报功课、计时和反馈，结果由家长核对；阅读与短引导分别逐项、逐题分享。孩子也可“用登记本 / 语音来报”；今天清单中的“核对报来的功课”供家长检查原件和解释，确认要求不等于确认完成。2026-09-08已完成时间管理家庭试用部署，桌面与窄屏隔离流程、正式入口读取及原有记录保留已核对；实际手机、家庭使用和节时效果尚待验证。具体规则见[PRD的FR18](PRD.md#fr18-放学后时间管理)。

## 主动陪伴的最小架构

现有Python后台、SQLite、附件与网页继续复用。`family_collect.py`通过已授权CLI采集，`family_agent.py --once`独立处理增量消息、学习记录及到期反馈；系统定时器定期执行，不依赖Codex会话。来源游标、工作状态和提醒保存在同一主库，网页只读取结果。首页孩子卡片显示少量有出处的提醒，学校草稿经家长核对后加入原有待办，学习跟进复用原记录反馈。已有即时整理与问答继续使用同一模型接口。没有增加Agent框架、向量数据库或另一套业务数据库。

场景顺序：考试前核查范围与困难，考试后记录错题、订正和复测；情绪与同伴交往从具体事件和孩子意愿出发；本地消息核查官方来源、有效期、适龄和成本。建议不承诺提分、不诊断、不自动报名。地点未知时不生成区域推荐。

旧版建议兼容路径由采集端写入私有目录的陪伴建议.json列表，经既有同步流程送到后台；独立Agent的新提醒和处理状态保存于主库，不写回该文件。旧文件不存在文件时显示空状态，损坏不影响其他记录。每条包含id、child、topic、title、evidence、action、review_on、expires_on。记录反馈使用既有records表，source为“陪伴建议:ID”；独立Agent定时复用其到期规则，过期旧建议不作为当前有效建议展示。图文草稿已经实测；本地语音转写已验证，讯飞数据直连仍待实现。成绩记录可通过“跟进 / 复测”关联订正、复测或补充观察，禁止关联到另一个孩子或形成循环。自有部署可通过经过认证的HTTPS反向代理提供手机入口，实际手机操作需要单独验证。

陪伴反馈沿用原表单，家长可选择“只记录反馈”“愿意试试”“暂不考虑”或“改天回看”，也可保留文字、照片及语音原件。明确选择保存后立即影响展示和回看安排；延期须指定北京时间今天之后的日期。“愿意试试”只表示意愿，不表示孩子已完成，不发奖励，也不延长过期建议。只记录反馈不改变原决定，不根据正文关键词猜测采纳或停推。

每次明确选择追加保存于原成长记录，新选择优先于旧提醒文件中的安排；更正早期记录的文字不会重新应用旧选择，调整选择须追加反馈。重复提交同一请求只保存一次，结果不明时用原请求核对重试；若已有更新选择，以后台当前安排为准。此状态与反馈历史随主库备份恢复。

`python3 test_followup.py`、`python3 test_review.py`和`python3 test_backup.py`包含选择、回看及恢复检查；`node test_care_ui.cjs`使用隔离虚构家庭核对360与1440 CSS像素下的明确选择、日期、失败重试与表单重置，沿用上述Playwright运行环境配置。此检查不代替真实手机操作或家庭回看反馈。

## 本地回看检查

初始化并运行应用后，在主库所在机器执行 `python3 family_review.py`。它复用现有孩子归属、建议与反馈读取规则，以北京时间检查到期或错过日期的建议，并输出需要核对的反馈；无需模型、Codex运行时或新增服务。独立目录可用 `--root 家庭目录 --data 私有目录` 指定，默认使用程序目录及现有 `FAMILY_DATA` 配置。

命令只读数据库、建议和提醒状态，原子保存权限为0600的 `private/回看检查.json`。完整待处理候选保留在报告中，实质内容无变化时标准输出为空；调用方仍须查看退出码与报告，空输出不等于没有未处理事项。退出码1表示存在读取或保存问题；故障时保留可核对的旧候选并标明当前来源无法核对，不能把来源缺失或损坏当成无需回看。

明确停推和延期继续有效；新的自由文本只作为待核对依据，不按关键词推断采纳、恢复推荐或孩子完成。过期建议需要重新核实，不自动续期。原件仅列关联ID并标记正文未读。检查报告不修改 `last_notified` 或家长状态，也不表示通知已送达；建议的解释、处理与通知仍由实际运行的Agent或家长完成。

该检查命令不自带调度器；独立Agent运行时直接复用同一到期规则，调度由操作系统负责。检查报告是可重建资料，不代替家庭原始备份，恢复后可重新生成。`python3 test_review.py` 使用虚构资料验证日期、停推延期、同孩反馈、只读与故障恢复；真实到期回看与家庭效果另行验收。

```sh
family_source_zip=/absolute/path/family-learning-source.zip
family_data_zip=/absolute/path/backup.zip
family_source_sha256=填写已保留的源码包SHA256
family_data_sha256=填写已保留的数据包SHA256
family_restore_work=/absolute/path/new-family-recovery
umask 077
python3 - "$family_source_zip" "$family_source_sha256" "$family_data_zip" "$family_data_sha256" <<'PY'
import hashlib, sys
from pathlib import Path
for name, expected in zip(sys.argv[1::2], sys.argv[2::2]):
    assert len(expected) == 64 and hashlib.sha256(Path(name).read_bytes()).hexdigest() == expected, '包的SHA-256不匹配，停止恢复'
PY
```

仅在上述校验成功后继续；工作目录必须是新目录，创建失败就停止，不复用其中的旧文件：

```sh
mkdir "$family_restore_work" &&
python3 -m zipfile -e "$family_source_zip" "$family_restore_work/source" &&
python3 "$family_restore_work/source/family_backup.py" restore "$family_data_zip" "$family_restore_work/recovered" &&
python3 -m zipfile -e "$family_source_zip" "$family_restore_work/recovered" &&
python3 - "$family_restore_work/recovered" <<'PY'
import os, subprocess, sys
from pathlib import Path
root = Path(sys.argv[1])
env = {key: value for key, value in os.environ.items() if not key.startswith('FAMILY_')}
env['PORT'] = '8766'
subprocess.run([sys.executable, str(root / 'app.py')], cwd=root, env=env, check=True)
PY
```

数据包不包含程序、反向代理认证文件、部署环境中的模型/转写密钥或桥接凭据；选定打印机设备配置随家庭数据备份保留。个人微信/QQ登录和系统调度安装状态也不在其中。Agent授权映射随数据备份；恢复时自动停用Agent，核对来源、主库及游标后再启用。切换正式服务前，另行恢复或重新配置自己的服务用户与启动目录、HTTPS及家长认证、儿童公开地址和Cookie路径、模型/转写端点、打印队列与独立桥接凭据；可选能力暂不配置时，先使用手动记录与原件查看。相关参数见下文模型、打印和儿童入口各节。确认认证入口与原件访问有效后，再恢复采集和桥接；不要把本次回环测试端口无认证公开。

## 模型配置与故障

后台支持Chat Completions与Responses接口，要求支持所用任务的图片及严格JSON Schema。Chat Completions填写API基础地址，Responses填写以`/responses`结尾的完整接口地址。家庭设置支持保存私有`private/model.json`；也可在服务器环境设置`FAMILY_LLM_BASE_URL`和`FAMILY_LLM_MODEL`，需要鉴权时设置`FAMILY_LLM_API_KEY`。已有环境配置优先且不能在网页覆盖。可选`FAMILY_LLM_LIGHT_MODEL`仅供文字学校通知筛选，与默认模型共用服务和密钥；留空继续单模型。可选`FAMILY_LLM_REASONING_EFFORT`只在两个模型均支持时设置，不同服务能力不能由接口名称推定。密钥不在网页响应中回显或写入公开仓库。

`model.json`与`model.env`均为机器专属模型配置，不进入家庭数据备份；本次恢复后已重新配置并通过真实固定合成文字调用。换机器或恢复家庭备份后仍需重新配置模型。资料、孩子和学习记录的恢复不依赖这些密钥。

已核对家庭模型配置及真实固定合成文字调用；自有服务器可经SSH反向隧道访问本机回环模型端口，公网不得转发模型接口。模型主机须开机、联网且服务运行，冷开机自动恢复仍待实测。识别故障不会阻止原件或手动记录保存。当前语音服务为本机WhisperKit，已通过虚构中文录音及服务重启验收。

常见情况：未登录返回401；服务重启后旧表单令牌失效时刷新重试；图片类型不支持时可保留原件并手动记录；模型未完成、离线或草稿结构错误时保留原件，不把错误结果写入成绩。浏览器显示“已配置”不等于此刻模型在线。恢复数据前先停服务，在空目录校验备份，再由管理员切换，避免覆盖主库。


语音服务使用`FAMILY_ASR_URL`配置完整转写端点（例如`http://127.0.0.1:12346/v1/audio/transcriptions`），可选`FAMILY_ASR_API_KEY`、`FAMILY_ASR_MODEL`（默认base）。服务须支持multipart file/model/language/response_format并返回JSON text；本项目只发送此次选择的音频。转写文字可编辑，不自动保存。中文人名、数字和方言仍需人工听原音核对，示例通过不代表所有录音准确。

本机WhisperKit CLI可用`whisperkit-cli serve --model base --language zh --host 127.0.0.1 --port 12346`启动；首次需下载对应模型及tokenizer，不包含在源码包中。基础应用无第三方Python依赖，模型服务独立安装。WhisperKit本次版本不能直接解码浏览器WebM，因此应用用后台已安装的`ffmpeg`经管道转成WAV，每段最多3分钟；缺少ffmpeg时仍保存原件并提示改传WAV、M4A或OGG。其他格式转写取决于配置服务的解码支持。服务无内置鉴权时只能回环监听，并通过受限隧道由后台访问。

当前源码包含网页后台、独立Agent、只读CLI采集器及系统调度模板，配置步骤见[AGENT运行.md](AGENT运行.md)。需要自行配置CLI登录、授权群、模型端点和服务路径；不含其他家庭登录态、模型权重或运行实例。到期回看不依赖模型；需模型的资料失败后保留并定期重试。站内提醒已提供，微信/QQ对话入口和站外推送尚未提供。

## 家庭打印

网页勾选一份或多份已归档附件、上传资料，选择单双面，可为每份文件指定页码，直接点击“提交打印”；不要求先打开预览或额外勾选确认。默认每份文件1份、黑白，打印机和份数等放在更多设置中。提交时自动准备固定PDF并检查每份文件的页码，全部准备成功后逐份入队；部分入队成功后只重试未完成文件，保留原请求编号。需要检查内容时可自行打开原文件。

支持原PDF、JPEG和常见非交错8位PNG。页数读取需要安装Poppler的 `pdfinfo`，可用 `FAMILY_PRINT_PDFINFO` 指定路径。Word `.docx` 和PPT `.pptx` 转换需要另装LibreOffice，并在服务器环境中设置 `FAMILY_PRINT_SOFFICE=/usr/bin/soffice`。含宏、外部资源或不支持格式会拒绝转换，可下载原件或另存PDF后上传。Office仍通过已有转换链路生成PDF，排版可能与原软件不同；简化网页操作不代表已改为打印机端排版。

打印原件最多20MiB、PDF最多50MiB及200页，每次1至10份且最多500个页面副本。桥接指定A4、每面1页、适配纸张；双面用纸按每份单独进位估算。PDF页序与教材印刷页码分别理解。预览和原件留在私有目录，预览本身不会发送打印。

后台在自有服务器时，家中Mac通过已有SSH回环隧道领取确认后的任务，再交给本机CUPS。先在Mac系统设置中配置家庭打印机，用 `lpstat -p` 核对准确队列名；Bonjour发现不等于已配置或已授权。服务器私有 `private/打印机配置.json` 格式如下，所有字段必需，名称与能力按实际设备填写：

```json
{"printers":[{"name":"Example_Printer","label":"示例家庭打印机","color":false,"duplex":true}]}
```

在后台和家中桥接进程的私有环境中配置同一个随机 `FAMILY_PRINT_BRIDGE_TOKEN`（至少24字符），与网页会话令牌及登录密码分开。桥接只接受本机回环URL，不直接向公网传凭据。单次运行示例：

```sh
python3 print_bridge.py --url http://127.0.0.1:18765 --printer Example_Printer --once
```

URL应为已建立的SSH转发端口。按实际部署用系统任务定期执行这条命令；本源码不会自行选设备或安装定时桥接。持久日志默认保存在家中电脑 `~/.local/share/family-learning/print-bridge`。未配置队列时，网页仍可选择文件和下载原件，但不能提交打印。

同一请求重复提交沿用任务编号。发送前持久记录，断线、超时、崩溃后不盲目重打；结果不明需先核对本机队列和纸张。CUPS接收、CUPS报告完成及家长确认取纸为三个不同状态。仅未领取任务可在网页取消，已领取任务需在本机打印队列核对处理。家长确认取纸不会自动把学校作业标记完成。

打印PDF随 `private/print` 备份，任务随SQLite备份，选定打印机设备配置也随备份保留；桥接凭据仍属于部署配置，需私下另行保管。恢复先验证归档哈希，再把未由家长确认的旧打印任务置为待核对，保留原状态与CUPS编号并撤销旧领取凭据，防止自动重放；这项保护会有意改变恢复数据库的哈希。切换恢复库前停止服务和桥接进程。

反向代理应保留后台对打印PDF预览返回的 `SAMEORIGIN` 和 `frame-ancestors 'self'`，不要额外附加 `DENY` 阻止本页预览。其他页面保持禁止外部嵌入，所有静态资源、API和PDF均须经过同一身份认证。软件的模拟队列回归不能代替真实打印机出纸验收。

邀请24小时内可用一次，登录7天后失效；家长可随时停用该孩子的全部邀请和登录，重新生成邀请会使旧的未使用邀请失效。邀请仅在生成时显示，不写入链接查询参数或浏览器持久存储。请在孩子自己的设备或没有家长登录态的独立浏览器使用；同一浏览器缓存着家长认证时，打开儿童入口不能撤销浏览器已有的家长权限。

本地开发入口为 `/child/`，与家长页面共用Python进程和SQLite；服务端只允许明确列出的儿童接口，所有资料归属根据儿童会话核对。独立入口当前覆盖功课、阅读与逐题分享的短引导，不表示已实现儿童全科教学、学校收件箱或完整的多角色后台。无模型可继续提交作品原件及文字；麦克风需要HTTPS或localhost及浏览器许可，实际手机与孩子试用仍需另行验收。

子路径部署必须保留儿童路径转发，例如将 `/family/child/` 代理到 `http://127.0.0.1:8765/child/`，不能代理到后台 `/`。儿童子路径使用应用的独立邀请认证，代理须移除家长Authorization；其余 `/family/` 路径使用已配置的应用家长认证。两者均按[单机手机HTTPS入口](AGENT运行.md#单机手机-https-入口)保留Cookie及HTTPS头，避免再叠加家长Basic弹窗。设置 `FAMILY_CHILD_COOKIE_PATH=/family/child/`、`FAMILY_CHILD_SECURE=1` 和 `FAMILY_CHILD_PUBLIC_URL=https://your-host.example/family/child/`，公开地址用于家长从SSH隧道管理时生成正确邀请。仅监听回环；不得将整个后台无认证暴露。Cookie为HttpOnly、SameSite=Strict，HTTPS部署要求Secure。

儿童邀请、会话哈希及作品归属随数据库备份；隔离恢复验证哈希后会清空旧邀请与登录，避免恢复已撤销的访问资格，家长需重新邀请。作品和已分享任务保留。恢复数据库因此会与备份中的字节哈希不同，原备份不被修改。

检查儿童入口：`python3 test_child_access.py` 验证服务端权限与提交来源；`node test_child_ui.cjs` 使用隔离虚构家庭与两个独立浏览器，检查分享、邀请、作品提交、家长确认、失败重试、撤销和360/400/1440布局。录音使用模拟麦克风，不能代替实际手机或孩子使用。浏览器依赖配置同前述 `test_startup_ui.cjs`。

## 学习对照回看

“学习进展”按已保存的同孩关联，集中展示原始尝试、订正、复测和补充观察。展开一条线索即可核对各次记录、分数、原件与直接关联的上一次记录，再点“记一次订正 / 复测”补记实际发生的尝试。新增记录仍沿用原表单，不要求先建立学习计划。

“学习这一步怎么完成的”是可选输入：本次帮助情况、与直接关联记录的材料关系、比较说明。空值保持未知；旧“独立复测”标签不自动证明独立完成，独立尝试不等于答对，相近新题不自动证明难度可比或已经掌握。日期差来自记录日期，同日或日期倒置会明确提示；缺失、跨孩或循环关联不能当成完整证据链。

这三个字段与原记录一起保存和更正，旧版本缺少字段时显示未知，随SQLite备份恢复；查询只使用实际填写的条件。旧客户端未提供新字段时保留已有值，家长明确清空才清空。不另建任务、自动打分或折算学习效果，复测记录获得的能量不因求助而扣减。`python3 test_followup.py`、`python3 test_growth.py`、`python3 test_backup.py`与`node test_learning_ui.cjs`使用虚构资料验证。本轮部署和浏览器验收状态见V1交付目标，真实学习效果仍需家庭实际尝试与后续回看。

## 消息来源状态与故障隔离

来源页优先显示独立Agent当前配置的全部群、孩子归属和最近读取结果；停用、暂停、失败、尚未读取及超过服务端下次读取时刻加5分钟轮询余量的待核对状态分别标明。当前状态复用已返回的Agent快照，不在打开网页时采集。旧采集JSON放在“历史采集记录与覆盖说明”中，不能覆盖当前状态。含未读图片、附件或截断内容的条数指已保存消息中的缺口，不是新消息数。历史记录分别保留上次成功、最近尝试、消息时间和历史增量登记。接入待验证或本次请求失败时保留旧资料，不把历史条数说成本轮新增，也不凭接口失败推断登录状态。每个来源的图片、文章、小程序和历史缺口可展开查看，并可转入对应孩子的待办清单；正文成功或零新增都不代表附件和全部历史已读。

“今天”同样显示来源异常和未读内容提醒，一键打开来源页核对具体群、上次成功与最近尝试。后台分别说明读取工具未接通、无法启动、读取超时、结果无法核对等已知故障；未确认的原因不推断为账号退出或权限拒绝。失败不新增消息，也不改上次成功位置；恢复后的下一次成功读取才清除错误。已有采集进程不会因发布而强制重启，新版读取工具错误码在该进程下次正常启动后生效。

采集状态JSON损坏、格式错误或读取失败时，API明确返回sync_error，来源页显示错误；已有家庭记录、阅读任务和手动跟进继续可用，不用空来源冒充没有消息。`python3 test_app.py`验证故障隔离，`node test_sources_ui.cjs`使用虚构资料检查来源状态、缺口、安全显示与窄屏操作。没有增加消息采集框架或网页直接控制聊天客户端的功能。
