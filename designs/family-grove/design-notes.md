# 一起成长 · Family Grove 设计说明

交互原型：`index.html`（同目录 `styles.css`、`app.js`）。用 HTTP 打开，例如 `python3 -m http.server 4311 --directory designs` 后访问 `http://localhost:4311/family-grove/index.html`。宽度 ≥ 900px 时显示 Mac 工作台，< 900px（含 360）时显示手机单列。演示数据都是虚构的（星星、小宇，演示日 2026-11-04）：不连接家庭后台，不真的上传或打印，不调用任何模型。界面里“AI 已整理 · 演示”和检查结果都是写死的示例。

## 方向

像一本放在木桌上的家庭作业本：米色纸面、嫩绿色表示“可以做 / 已办”，木色做科目木牌，珊瑚色只用在“明早交”和需要家长看一眼的地方。可爱感只放在小处：
- 叶形勾选：已办时圆圈会长成一片叶子；
- 带钉眼的木牌标出科目；
- 按钮底部有 3px 的厚边，按下会沉一下；
- 已整理的资料卡内圈有缝线；
- 原消息用对话气泡显示。

不用大插画、吉祥物、emoji 或渐变，没有大号问候语，也不用任天堂的角色、图标或贴图。动森只借了温暖、自然、触感这种气质。

## 信息结构

- **一次只看一个孩子**：工具栏用分段控件在两个孩子间切换，没有“全部”。
- **当天清单**：按语文、数学、英语、综合平铺。每一行直接写出四样东西：
  - 做什么和范围；
  - 完整完成标准；没有就写“完成标准未提供，待补充”，不替谁补；
  - 完成日和交回日（只有“明早交”用珊瑚色）；
  - 资料份数，以及其中尚未读清的份数。

  老师名和发布时分只作一行小字出处。
- **不计入当天的事项**：课内安排（例如课堂听写）和没写日期的事项放在“课内 · 未定”里。当天清单底部会注明“另有 N 项，不计入”。没写日期的事项不猜日期，家长可以手动定在明天或后天，界面会标“日期由家长补上”。课堂上做但日期未知的事项仍是课内安排，只在“日期未写明”里出现一次。日期未知写成“日期未写明 / 日期未知，不猜”，不说成“老师没写”。
- **原消息**：只列与本项有关的原话，补充和更正按时间排在后面。另一位老师的相关消息单独显示并注明“没有合并”，并给出它被单列到的日期。
- **资料**：角色和状态分开表达。
  - 角色：原卷、教师答案、家长参考、原件。
  - 状态：原件已保存、AI 已整理、尚未读清（虚线框）。
  - 已整理的资料显示提要、页码和下一步；未读清的资料只说明原因和下一步（例如“订正格式尚未读清，请看原件”），不显示猜测的内容，也不断言它不影响作业。
- **打印**：“打印原卷”和“打印家长参考”是两个独立的单击入口。打印前的确认里写明依据是哪条原消息。依据之后有补充或更正时，打印按钮先锁住，家长点“我已核对新依据”后才能打印。
- **同一份作业里完成整条流程**：
  1. 交作答照片（上传成功只算“照片已保存，还没检查”）；
  2. 开始检查；
  3. 结果汇总为“n 对 · n 错 · n 待你看”，AI 疑点只需家长看这一题；
  4. 错题可以“看原答”，标“订正好了”，也可以“重开订正”。

  进度只说已办和待办，不出现掌握度、分数、情绪或排名。
- **文字反馈和手动错题（每一项都有）**：
  - 没有照片检查的事项、口头补录和课内安排也一样。“写文字反馈”在弹出层里写，照片可加可不加，不调用 AI；保存后记在同一项下，重开还在。
  - 保存文字不会自动标已办，也不会自动判错。再写一条、再交照片检查，都不覆盖已保存的反馈和错题（包括订正状态）；照片检查的“n 错”只数检查出的错题。
  - 已保存的反馈下可以“记一道错题”：哪一题必填，原因和照片可不填。它和检查出的错题共用待订正 / 已订正 / 重开订正，也进入“错题订正”，只是不显示原答和教师答案。
  - 有未保存的内容时，关闭或按 Esc 会先询问，默认“继续编辑”；保存失败保留文字和照片，可以重试。
- **补录口头作业**：
  - 科目和“要做什么”必填，其余可以不填；
  - 来源自动记为“孩子口头转述”；
  - 交回默认“还不知道”，保存为“交回日未知”，不推断成明早交；做的日子默认是家长正在看的这一天，可以改成明天或“还不知道”；
  - 可以标“课堂上做，不算家庭作业”；日期也不知道时仍按课内安排保存，不改成家庭作业。

  有未保存的内容时，取消会询问，默认“继续编辑”。保存失败时保留全部输入，并可以重试。保存中按钮锁住，防止重复写入。

## 演示控制与状态

- 状态只归 `App` 一处管理，存进本机 `localStorage`，刷新后状态还在（保存后重开）。重开时，没跑完的“检查中”会退回“照片已保存”，不会显示成检查完成。
- 右上 ⋯ 菜单里有两项演示操作：“让下一次保存失败”（作用于补录、上传、文字反馈、记错题、订正），以及“重置演示数据”。

## 视觉 tokens（`styles.css :root`）

| 用途 | 变量 |
|---|---|
| 纸面 / 卡片 / 桌面 | `--paper #FBF6EA` · `--card #FFFDF7` · `--desk #EAE0CA` |
| 文字 | `--ink #3B3326`（约 11:1）· `--ink-2 #665A48`（在 `--paper` 上约 6.2:1） |
| 嫩绿 | 填充 `--leaf-300 #A8D978`，按钮文字 `--leaf-800 #1F4A1C`（约 6.3:1） |
| 木色 | `--wood-100 #F1E2CC`，文字 `--wood-700 #6B4520`（约 6.6:1） |
| 珊瑚 | `--coral-100 #FDE6DD`，文字 `--coral-700 #A13F2A`（约 5.4:1） |
| 字体 | 标题和控件：`ui-rounded` → 圆体-简 → 苹方；正文：系统字体 → 苹方。不加载外部字体 |

- 所有可点区域至少 44px（包括孩子分段、手机视图切换、菜单项和提示条里的按钮），键盘焦点是 3px 的绿环。
- `prefers-reduced-motion` 打开时关闭所有过渡和动画。
- 窗口宽度在 900–1179px 之间时，导航收成图标栏；完成、交回、所需收成一张卡里的三行（手机同样），每条事实和日期都保留。≥ 1180px 仍是三张并排的事实卡。
- 手机：清单顶部随页面滚动，不固定；详情的返回条和底部按钮固定，页面设了 scroll-padding，滚到或用键盘聚焦的控件不会停在固定条下面；底部按钮上方的渐隐区不拦截点击。

## 原生落地决定（Mac）

**已核实的现状**
- `packaging/macos/Sources/main.swift` 是 AppKit + WKWebView 薄壳，整页加载本机服务。
- `app.py` 的 `/api/state` 返回 `snapshot()` 整库（任务、记录、上传、历史）。
- “一个孩子一天”的组装分散在两处：当前网页 `calendar.js` 的 `todayTasksHTML`（由 `app.js` 的 `render` 调用），以及 Python 的 `family_agenda`（由 `test_daily_list_whole_day.py` 覆盖）。

把这个网页放进另一个框，不算原生。

**主选方案：SwiftUI 原生每日工作台**
- **布局**：`NavigationSplitView` 三栏。
  - 侧栏：今天、课内 · 未定、错题订正；
  - 中栏：按科目分组的 `List`；
  - 详情栏：所选事项。
- **工具栏**：`.toolbar` 里放孩子分段 `Picker`、日期步进和“补录”。
- **菜单**：用 `Commands` 提供菜单栏命令：

  | 命令 | 快捷键 |
  |---|---|
  | 补录口头作业 | ⌘N |
  | 前一天 / 后一天 | ⌘[ / ⌘] |
  | 回到今天 | ⌘T |
  | 切换孩子 | ⌘1 / ⌘2 |
  | 打印原卷 | ⌘P |
  | 打印家长参考 | ⇧⌘P |

- **弹出与查看**：补录、交照片、写文字反馈、记错题、打印用 `.sheet`。原件 PDF 和图片用 PDFKit / Quick Look 打开。
- **WKWebView 的范围**：只用于富文本原件，以及过渡期还没重做的次级旧页面（设置、老师、成长等）。
- **图标**：SF Symbols，对应关系见下表。

**数据只做薄投影**
- 在 Python 端新增一个只读的当日投影，接口名在实现 PR 里定，例如 `GET /api/day?child_id=&day=`。
- 投影直接给出已经归类好的结果：
  - 按科目分组的家庭作业、课内安排、未写日期的事项；
  - 每项的完成日和交回日、完成标准、出处、原消息引用；
  - 资料的角色、三种状态、提要、页码和下一步；
  - 反馈进度和错题数。
- 投影必须复用现有 Python 规则，不另写一套。如果某条归类规则现在只在网页 JS 里，先把它移到服务端，用现有测试和新增快照测试守住，让网页和 Swift 读同一份投影。
- Swift 端只解码（`Codable`）和渲染。日期角色判断、来源合并、不同老师不合并、打印依据核对都留在服务端，Swift 不重写。
- 写入沿用现有接口，例如 `/api/upload`、`/api/task/feedback`、`/api/print/homework`、`/api/wrong/save`、`/api/record/task-create`。每个操作具体对应哪个接口，在实现 PR 里逐一核对。打印仍走服务端已有的依据核对，原生端不绕过。
- 连接、登录和同源规则沿用 `DesktopPolicy` 的现有约束，仍然只有一个后台、一个主库。安装器工作树完成后再接入，本次不改 `packaging/`。

**手机**
- 同一个 `app.py` 网页按这套设计重做为 360 单列。详情页压入浏览器历史，系统返回手势和返回键能退回清单。
- 读同一份当日投影，不另建 iOS 原生应用。

## 未包含

- 深色模式、iPad、真实数据的长文本和极端数量还没有设计。
- `assets/original-sprout.png` 没有制作：本机没有可用的原创插画来源，按要求留白。
- 这是设计原型，不是产品版本；视觉验收由 Root 在浏览器里完成。M4 上没有浏览器，本机只做了 Node 交互检查和静态检查，没有看过渲染结果。

## Root集成核对

现行主入口是`app.js render(home) → calendar.js todayTasksHTML()`；旧`homeHTML/todayChildHTML`不是当前首页，不据其文字判断现行清单。原型错题页按状态分区只演示同项订正；正式版仍须按科目作为第一分组，状态作为行标记。原生接入保留这一要求，设计稿不作为此项已实现证据。
